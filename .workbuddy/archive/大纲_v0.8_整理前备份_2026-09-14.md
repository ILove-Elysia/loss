## 第一章：项目立项概述

### 1.1 游戏定位

| 项目 | 内容 |
|------|------|
| 游戏名称 | 《Lost Land》/ 失落之岛 |
| 游戏类型 | 3D 俯视角（饥荒式）生存建造游戏 |
| 核心玩法 | 采集 → 合成 → 建造 → 探索 → 战斗，以电量/体温/饱食度三条生存指标驱动 |
| 目标平台 | Steam PC（设计基准 1280×720，canvas_items 拉伸，任意分辨率等比） |
| 引擎 / 语言 | Godot 4.7 + GDScript |
| 开发阶段 | Demo 已可跑通核心循环，EA 阶段补内容 |

### 1.2 游戏简介

《Lost Land》是一款 3D 俯视角生存建造游戏。玩家可从**冒险家 / 魔女 / 机器人**三位角色中选一位开局（✔ 已实装，另含 3 个测试角色），每人拥有一套**专属制作栏**与**专属系统**。三人都在**孤岛中央**醒来，岛上没有救援，玩家需要采集资源、合成工具、搭建营地、探索六大区域，在体温与饥饿的压力下活下去，弄清这座岛为何会被世界遗忘。

**与常规生存游戏的区别（v0.8 定稿）：** 三位角色的**基础数值完全相同**（生命 100 / 移速 ×1.0 / 攻击 ×1.0），差别**全部来自系统，不来自数字**。机器人多背一条"电量"线 —— 它是唯一**开局就有电量**的角色，过冷过热会额外漏电，电量归零会掉血，但电量充沛时也能缓慢自愈；冒险家与魔女默认没有电量，过冷过热**直接扣血**，回血**只能靠吃食物**，日后可拾取「动力核心」解锁外置电量。同一个岛，三种活法。

### 1.3 开发背景与目标

**开发背景：**
- 玩家是编程新手，代码需要详细注释与集中式数值配置（数值都放在注册表 / `@export` 里，不散落在逻辑中）
- 已有 Godot 4.7 项目基础，实装量见 6.1

**开发目标：**
- **第一阶段 Demo ✔**：核心生存循环、采集/合成/建造、2 种敌人、昼夜、存档
- **第二阶段 EA ○**：补齐 6 大区域内容、更多敌人、地下遗迹、魔法系统
- **第三阶段 完整版 ○**：完整剧情、多结局

## 第二章：游戏整体设计

### 2.1 世界观

> **本版定位：背景暂时搁置，优先做游戏内容。** 本节只保留"能解释玩法"的最小设定；完整的远古文明剧情留到 EA / 完整版再展开（○），旧稿存档见 2.1.3。

#### 2.1.1 背景故事（最小可用版）

一场突如其来的海难，把你抛上了这座四面环海的孤岛。

**你在孤岛正中央醒来**，浑身是伤、记忆残缺 —— 只记得自己是个四处漂泊的冒险家，却怎么也想不起是怎么来到这里的。身上一样东西都没剩下：没有工具、没有食物、没有同伴。

岛上有森林、矿区、火山与雪原，却没有救援、没有同类，只有游荡的怪物。你必须先活下来 —— 采集、合成、搭营地，再往岛的深处走，弄清这座岛为什么会被世界遗忘。

> **注（v0.6）：** 上面这段是**冒险家**线（也是当前的默认叙事）。魔女与机器人各有自己的开局与来历 —— 两者是否共用这条"孤岛醒来"的开场，还是各写一段，见 2.2.7-⑥。

#### 2.1.2 世界分层

**✔ 已实现：表层** —— 平面世界，无海拔高差（同心圆环分布，见 4.2）

```
                        ┌───────────────────────────────┐
                        │        【失落之岛】表层         │
                        ├───────────────────────────────┤
                        │  Tier 0 内圈 ─ 草原区（出生·中央）│
                        │  Tier 1 中圈 ─ 丛林 / 矿区 / 沙地 │
                        │  Tier 2 外圈 ─ 火山 / 雪地       │
                        │  岛缘 ─ 沙滩 ├ 外围 ─ 无尽海洋    │
                        └───────────────────────────────┘
```

> **Tier 0 内圈（草原区）就是孤岛的正中央，也是玩家的出生点。**

**○ 规划中：深层** —— 机械文明遗迹（地下世界）：机械遗迹入口 / 废弃工厂 / 能量核心室。当前 Demo 无地下内容；`task_system` 里"地下遗迹"相关特殊点仅作为区域标签预留。

#### 2.1.3 旧背景设定（搁置存档）○

以下是 v0.3 沿用下来的远古文明背景。**当前不投入开发，也不在正文引用**，仅作为将来真做剧情时的素材保留：

- 远古文明 **"织星者"**：掌握魔法与机械，建造过悬浮的机械遗迹大陆
- 灾变 **"大静默"**：魔法核心失控，机械大陆坠入地下，岛屿被无尽海洋隔离
- 备选剧情线：主角实为织星者的最后一台类人机器人，在沙滩启动、寻找能量来源
- **本版已废弃的旧设定**：主角是机器人、沙滩出生、地下遗迹属于 Demo 内容

> 说明：**动力核心**这个词沿用自旧设定，但本版已彻底改定位 —— 它不是主角体内的东西，而是**探索途中拾取的遗物**（见 3.1.3）。本版同样不解释它的来历，来历作为悬念留到以后（见 6.3）。

#### 2.2.3 三个正式角色的数值与特色对比（✔ v0.8 已实装）

| 项目 | 冒险家 | 魔女 | 机器人 |
|------|--------|------|--------|
| 生命值 | 100 | 100 | 100 |
| 移速倍率 | ×1.0 | ×1.0 | ×1.0 |
| 攻击倍率 | ×1.0 | ×1.0 | ×1.0 |
| **电量系统** | ✗ 无（可解锁） | ✗ 无（可解锁） | ✓ **有，100/100** |
| **电量语义（3.1.0）** | 无 → 装入核心后**外置** | 无 → 装入核心后**外置** | **内置** |
| 生存指标 | 体温 + 饱食度 | 体温 + 饱食度 | 体温 + 饱食度 + **电量** |
| **过冷 / 过热惩罚** | **扣血** ＋ 漏电量（如果有） | **扣血** ＋ 漏电量（如果有） | **扣血** ＋ **漏电量** |
| **回血方式** | **吃食物** | **吃食物** | 吃食物 ＋ 电量 > 80 时的自然回血 |
| **开局 / 解锁** | **默认可选（开局角色）** | ○ 游戏内途径解锁 | ○ 游戏内途径解锁 |

**设计意图：三个角色基础数值完全相同 —— 差异全部来自"系统"，不来自"数值"。**

- 好处是**不用反复平衡强度**：玩家选角色时比的是"想要哪种玩法"，而不是"谁更强"。加新角色也只需设计系统，不用重算一遍数值表。
- **过冷 / 过热统一为"扣血 +（有电量则）漏电"**：所有角色都扣血，火山 / 雪地对谁都有压力；有电量的角色**额外再漏一份电**。
- **机器人因此承受双份惩罚**（扣血 + 漏电），这是它"多一条补给线（电池）"要付的代价；若实机觉得过重，优先下调漏电速率而不是取消扣血。
- ✔ **回血出口（v0.8 实装结果）**：
  - **吃食物**是**所有角色通用**的回血手段（浆果 `+25_food +10 HP`，饱食度满时整次进食作废 —— 防"背包塞满浆果＝无敌"）。
  - **自然回血是内置电量的专属福利**：只有机器人能靠"电量 > 80 且吃饱"缓慢回血（+5 HP/分钟）。
  - **外置电量（装上动力核心的冒险家 / 魔女）不回血** —— 外置电池对人物本体**零影响**，既不扣血、不减速，也不给回血（用户决策 2026-09-14，见 3.1.0）。

> **待平衡项：** 扣血速率按"漏电 -0.5/秒"等量换算（见 3.2.2），机器人是否因双份惩罚而需要下调其一，实机再调。

#### 2.2.4 角色专属系统

**① 电量系统 —— 机器人专属（✔ v0.8 已实装，含按角色开关）**

| 项目 | 说明 |
|------|------|
| 谁会掉电 | **仅机器人**（内置）。冒险家 / 魔女默认没有电量，HUD 的 ⚡ 行显示**灰色占位** `⚡ --`（不是隐藏，见 5.1） |
| 谁受这些影响 | 见 **3.1.0 两种电量语义**：`<10` 减速、`=0` 掉血、`>80` 自然回血 —— **只对内置电量（机器人）生效**；过冷过热**漏电** —— 有电量的角色（含外置）都生效 |
| 过冷 / 过热的扣血 | ✔ **已实装（决策 ③）：所有角色都扣血**（-0.5 HP/秒），有电量的角色**再额外漏电**（-0.5 电量/秒）。见 3.2.2 |

**④ 专属物品的通用性 ✔（决策 ⑦，v0.8 已实装）**

**实现方案：`ItemData` 三个字段 + 使用权限三档**（不是"能不能捡"，而是"能不能用"）。

| 字段 / 枚举 | 说明 |
|------|------|
| `exclusive_owner` | 归属角色 id（如 `&"robot"`），只影响提示文案与加成判定 |
| `access_policy` | `ANYONE`（谁都能用）/ `OWNER_BONUS`（谁都能用，归属角色**效果加成**）/ `OWNER_ONLY`（**只有归属角色能用**） |
| `owner_bonus_mult` | `OWNER_BONUS` 时的效果倍率（如 ×1.5） |

> **只卡"使用"，拾取 / 携带一律放开** —— 专属物品可能出现在宝箱里被别的角色捡到，捡到却不能用只让人窝火，但"捡都不让捡"更糟。判定点在 `ItemEffects.access_denied_reason()`，`apply()` 里**再判一次**（保证任何新调用方都绕不过）；被拒时 HUD 弹提示条（`HUD.show_toast()`），悬停说明里用彩色行标出"加成生效 / 被拒"。

**当前 6 件专属物品的权限现状**

| 物品 | 归属 | 策略 | 说明 |
|------|------|------|------|
| 草药绷带 `herb_bandage` | adventurer | ANYONE | 谁都能用来回血 |
| 干粮 `trail_ration` | adventurer | ANYONE | 同上 |
| 治疗药剂 `healing_potion` | witch | ANYONE | 同上 |
| 活力药剂 `vigor_draught` | witch | ANYONE | 同上 |
| 高容量电芯 `power_cell` | robot | **OWNER_ONLY** | 只有机器人能用（+60 电量），别人用了没意义 |
| 维修包 `repair_kit` | robot | **OWNER_BONUS ×1.5** | 谁都能用来回血，机器人用效果 ×1.5 |

> **取舍理由（不变）：** 完全锁死会让玩家"捡到一件好东西却只能扔掉"，体验很差；完全不差异又会让"专属"失去意义。折中做法 = **基础功能通用、加成专属**。
> **◆ 仍未接线：** 专属**装备**的权限（`equip_slot` 目前不判 `access_policy`）—— 现在只卡"使用"，装备谁都能穿。

## 第三章：核心系统详细策划

### 3.1 电量系统 ✔（**机器人专属** · v0.6 收窄 · v0.8 细化内外置）

电量是**机器人**维持运转的第一资源，**不随时间自动消耗**。机器人本就以电力驱动 —— 电量是它的**固有属性，开局自带，不需要任何道具**。

> **角色归属（v0.8）：** 只有机器人有电量。**冒险家 / 魔女默认没有电量** —— HUD 的 ⚡ 行是灰色占位，下列"影响人物本体"的效果（低电减速、归零掉血、高电回血）一律不生效。
> **✔ 两点已实装（见 2.2.7）**：① 他们没有电量，但**过冷 / 过热改为直接扣血**（等量，见 3.2.2），不是免疫；② 想在其他角色身上开启电量，必须拾取「动力核心」并装入（见 3.1.3）—— 但装入的是**外置电量**，规则与机器人并不完全相同，见 3.1.0。

#### 3.1.0 两种电量语义 ✔（内置 / 外置 · v0.8 新增）

**分界线：`power_embedded`（电量能否影响人物本体）。** 这是 v0.8 最重要的一条规则 —— 外置电量**不是"机器人的电量换个皮"**，它对人物本体**零影响**。

| 效果 | 内置（机器人） | 外置（冒险家 / 魔女装核心） |
|------|---------------|---------------------------|
| 过冷 / 过热**额外漏电** | ✅ | ✅（环境在耗这块电池） |
| 电量归零**掉血**（-1 HP/秒） | ✅ | ❌ |
| 低电（≤10）**减速** ×0.7 | ✅ | ❌ |
| 电量 > 80 且吃饱**缓慢回血**（+5 HP/分） | ✅ | ❌ |
| 能否关闭 | ❌（`set_has_power(false)` 被拒并告警） | ✅（可拆，拆除后电量清零） |
| 回血出口 | 吃食物 **+** 自然回血 | **只有吃食物** |

- 内置电量由 `power_embedded = true` 标记（**仅 robot**），来自注册表，运行时不变 —— 动力核心是外挂设备，不会把角色变成"内置"。
- **唯一共有的是过冷 / 过热漏电**：环境在耗这块电池，与电池装在哪无关。
- ⚠ `has_power` 是**运行时状态**（核心可装可拆）→ 查"这个角色现在有没有电量"请读 `vitals.has_power`，**不要**用 `CharacterRegistry.has_power()`（它只返回开局默认值）。

#### 3.1.1 参数

| 参数 | 数值 |
|------|------|
| 最大 / 初始电量 | 100 / 100 |
| 自动消耗 | 无 |
| 特殊消耗 | 过冷或过热时每秒 **-0.5**（见 3.2.2） |
| 补充 | 电池 `+10`（可合成）；大型电池 `+50`（○ 未来 · 与"动力核心"是两回事：**核心＝解锁电量，电池＝补充电量**） |

#### 3.1.2 电量状态影响

| 电量范围 | 状态 | 影响（**仅内置电量 / 机器人**，见 3.1.0） |
|---------|------|------|
| > 80 | 充沛 | 生命值自然恢复 **+5 HP/分钟**（需同时满足"不饿"，见 3.3.2） |
| 11 ~ 80 | 正常 | 无 |
| ≤ 10 | 低电量 | 移动速度 **×0.7** |
| = 0 | 濒危 | 每秒 **-1 生命值** |

> 生命恢复用累积器结算整数 HP；恢复条件是 **电量 > 80 且 饱食度 > 20 且未满血**。
> **门禁是 `has_power and power_embedded`** —— 外置电量（装上核心的冒险家 / 魔女）**不回血也不掉血**，回血只能靠**吃食物**（见 3.3.2）。
> 外置电量唯一保留的被动是**过冷 / 过热漏电**（见 3.2.2）。

#### 3.1.3 动力核心 ◆（探索途中拾取 · 电量的解锁道具）

> **定位修订（v0.7）：** 动力核心**不再是开局就嵌在主角体内的东西**。它是一件**探索途中的拾取物** —— 来历不明的遗物，装到谁身上，谁就有了电量。

| 项目 | 内容 |
|------|------|
| 类型 | 可入包物品（id 拟定 `power_core`）；**不是装备、不是消耗品** |
| 获取 | **探索途中拾取**（◆ 决策 ④）。拟定投放点：**地下遗迹**的台座 / 战利品箱；具体位置与是否多处投放 ○ 待设计 |
| 作用 | 装入 → **解锁外置电量 100/100**（**语义见 3.1.0**：不掉血 / 不减速 / 不回血，只保留漏电与耗电交互） |
| 对机器人 | 机器人**开局自带电量，不需要核心**（○ 是否另给它"扩容 / 备用能源"用途，待定） |
| 可否拆除 | **可以**（◆ 建议）：装拆双向，解锁是一次**主动的风险交易**，不是单向陷阱 |
| **实装状态** | **◆ 接口已备、本体未做**：`vitals.set_has_power(active)` 已实现（装入满电 / 拆除清零 / 内置角色拒关并告警），但**没有调用方** —— 缺物品、投放点、装入入口与存档字段，玩家在游戏里走不到这条线 |

**接口契约（已就位，做物品时照此接线）：**

```
vitals.set_has_power(true)   → has_power = true，current_power = 100（满电解锁）
vitals.set_has_power(false)  → has_power = false，current_power = 0（拆除清零）
                               内置电量（robot）调用会被拒绝并告警
```

HUD 不需要额外接线 —— `vitals._push_hud()` 会自动在"占位 `⚡ --`"与"亮起 `⚡ 100`"之间切换（见 5.1）。

**为什么改掉"开局嵌入体内"**

1. 原设定里主角一醒来就靠核心吊命，等于**电量是开局白送的** —— 既削弱了探索动机，也和"电量是机器人专属"直接打架（冒险家开局就有电，那机器人还专属什么）。
2. 改成拾取后，电量变成**探索的回报**，和"往岛的深处走"这条主线同向。
3. 三个角色的差异能一直保留到玩家**真正做出选择**为止，而不是开局就被抹平。
4. 核心的来历自然成为悬念，不必在开场硬解释 —— 符合 2.1 把背景做轻的方向。

> **连带修正：** 背景故事 2.1.1 中"靠核心吊命"一句已删除；1.2 简介不再提"体内核心"。另外 3.3 里"吃饱与**动力核心**回血绑定"的说法也不成立 —— **绑定的是电量，不是核心本身**，已顺带改正。

### 3.2 体温系统 ✔

体温反映冒险家的冷热状态，由所处地形与热源驱动。

#### 3.2.1 参数

| 参数 | 数值 |
|------|------|
| 正常区间 | 10 ~ 40（无影响） |
| 过冷区间 | -10 ~ 10 |
| 过热区间 | 40 ~ 80 |
| 绝对值范围 | -100 ~ 100 |
| 自然回温目标 / 速率 | 趋向 30，**10/分钟** |

#### 3.2.2 体温影响

| 体温区间 | 所有角色（✔ 决策 ③ 已实装） | **有电量时额外** |
|---------|---------------------|------------------|
| 10 ~ 40（正常） | 无 | 无 |
| -10 ~ 10（过冷） | 每秒 **-0.5 生命值** | 每秒 **-0.5 电量** |
| 40 ~ 80（过热） | 每秒 **-0.5 生命值** | 每秒 **-0.5 电量** |
| < -10 或 > 80 | 持续扣血（○ 尚未加额外惩罚） | 持续漏电（○ 尚未加额外惩罚） |

> **统一规则（✔ v0.8 已实装）：** 温度惩罚**先扣血**（对所有角色生效），**再额外漏电**（仅对有电量的角色，含外置）。这样火山 / 雪地对谁都有压力，不会因为没有电量就白送难度；机器人则双份承担 —— 这是它多一条补给线要付的代价。
>
> **实现位置：** `vitals._update_power_effects()` 第 1 段。数值要分开调也是同一处（`extreme_temp_damage` / `extreme_temp_power_drain`）。
>
> **顺序：** `_tick()` 里是 **体温 → 饱食度 → 电量**；体温异常扣的血与其他来源（饥饿 / 低电）共用同一个 `_damage_acc` 累积器，满 1 点才扣整数 HP。
>
> **设计取舍：** 之所以选"扣血"而不是"减速"，是因为减速只是拖慢节奏、不会真的逼玩家撤退；扣血会直接把"带够补给 / 早点回营地"变成硬需求。而**回血出口已定为吃食物**（见 3.3.2），两者是配套的，必须同批实装。

#### 3.2.3 各区域体温变化

| 区域 | 体温变化 | 说明 |
|------|---------|------|
| 草原区 / 丛林区 / 矿区 / 沙地区 / 沙滩 | 趋向 30，10/分钟 | 自然回温 |
| 火山区（地形 14） | **+15/分钟** | 持续升温，久留必过热 |
| 雪地区（地形 15） | **-15/分钟** | 持续降温，久留必过冷 |
| 熔炉附近（5 米内） | 趋向 **35 度**，20/分钟 | 热源**压过**地形影响 |
| 地下遗迹 | — | ○ 未实装（Demo 无地下区域） |

> **设计修订说明：** v0.3 写的是"熔炉附近 +5/分钟"。但雪地区降温是 -15/分钟，+5 完全是净流失 —— 熔炉等于没用。改成"趋向目标温度"后，雪地里烤火体温稳定在 ~34 度，熔炉才真的能救命。

### 3.3 饱食度系统 ✔（v0.3 未定义，本次补上）

冒险家和常人一样需要进食补充体力，所以会饿：饿到阈值会减速、掉血，而 **吃食物是回血的主要手段**（◆ 决策，见 3.3.2）—— 于是吃饭这件事变得和打架一样重要。

#### 3.3.1 参数

| 参数 | 数值 |
|------|------|
| 最大 / 初始饱食度 | 100 / 100 |
| 消耗速率 | **100 / 480 每秒** —— 一个游戏日（480 秒）从全饱掉到空 |
| 饥饿阈值 | ≤ 20 |
| 温饱阈值 | ≥ 80 |
| 饥饿惩罚 | 移动速度 **×0.9**，且**停止自然回血** |
| 归零惩罚 | 每秒 **-0.5 生命值**（比电量归零的 -1.0 温和，留出找食物的时间） |

#### 3.3.2 回补方式（饱食度 / 生命值）

| 方式 | 效果 | 说明 |
|------|------|------|
| 浆果 berry | **`+25 饱食度` ＋ `+10 生命值`**（◆ 回血量为建议值） | 空手可采，浆果丛 240 秒再生 |

> **为什么必须同时落地食物：** 没有食物的话饱食度就是个只降不升的死亡计时器，所以配套实装了浆果资源与物品。
> **✔ 回血规则（v0.8 实装）：** **吃食物 = 补饱食度 且 回血**，一起结算。这是**所有角色通用**的回血手段；**只有机器人**另有"电量 > 80 且吃饱"的缓慢自然回血（+5 HP/分钟）作为额外福利（外置电量不回血，见 3.1.0）。
> **✔ 防滥用（已落地）：** **饱食度已满时整次进食作废**（含回血）—— 判断在结算**之前**，否则"满着肚子啃浆果回血"会绕过这道门槛。
> **多值效果：** `item_effects.gd` 支持**一条效果改多个值**（正则 `\+([0-9.]+)_(power|food|health)` 逐个结算，空格 / 连写都行）。
> **调难度：** 只改 `hunger_drain_rate` 一个值（调小更宽松，如 100/960 = 两天才饿一次）。

#### 3.3.3 移速惩罚合并规则

低电量与饥饿**不相乘**，取更狠的那个（`minf`）—— 相乘会让残血玩家几乎走不动路。

| 状态 | 移速乘数 |
|------|---------|
| 正常 | ×1.0 |
| 仅饥饿 | ×0.9 |
| 仅低电量（**内置**） | ×0.7 |
| 又饿又没电（**内置**） | ×0.7（取小值，不是 0.63） |

> 外置电量（装核心的冒险家 / 魔女）**不参与**低电减速 —— 见 3.1.0。

### 3.4 生命、死亡与复活 ✔

#### 3.4.1 伤害计算

```
实际伤害 = max(1, 敌方攻击力 - 玩家防御力)
```

护甲减免但**至少掉 1 点**，避免堆防御后完全无敌。

#### 3.4.2 死亡条件

| 死因 | 判定 |
|------|------|
| 生命值归零 | 被敌人打死 / 电量归零持续掉血 / 饥饿归零持续掉血 |
| 落水 | 脚下地形 = 海洋（7）且 y < **-0.6** —— 海水无碰撞体，走进去就是自由落体 |

#### 3.4.3 死亡 → 复活流程

```
死亡 → 屏幕滤镜转灰暗（FilterSystem.FILTER_DEATH）+ HUD 底部中央 5 秒倒计时
     → 倒计时结束 / 点击"复活"按钮 → 原地满血复活（体征重置、滤镜清除）
```

- 敌人目标判定统一走 `Physics.is_alive()`：玩家一死，史莱姆与无人机**立刻放弃追击 / 停火**，复活后自动重新锁定
- 死亡处理幂等（不会重复触发倒计时）
- 复活时 `Physics.revive()`：**满血 + 体征 reset + 清滤镜 + `camera_3d.snap_to_target()`**（不吸附镜头会从旧位置"飞"两三秒）
  - 体征 reset 的电量：`initial_power if has_power else 0.0` —— 没装核心的角色不该因为复活而凭空满电

**滤镜系统（`script/fx/filter_system.gd`，✔ v0.8 实装）**

| 滤镜 | 触发 |
|------|------|
| `DEATH` | 死亡（灰暗） |
| `LOW_HEALTH` | 低血量常驻 |
| `HIT` | 受击瞬间（脉冲） |
| `BURN` / `FREEZE` | 过热 / 过冷（○ 预留未接线） |

- 与昼夜系统**共用 `map.tscn` 的 `WorldEnvironment`**，`tick(delta)` 由 `hud_ui._process` 驱动
- ⚠ **只能写 `Environment.adjustment_enabled / saturation / brightness / contrast`** —— Godot 4 没有 `adjustment_color`，也没有 `vignette_*`；要染色或暗角只能上全屏 `ColorRect` shader

#### 3.6.8 开局破局链（核心循环）

```
空手捡小石块 pebble + 草 grass
   → 合成【粗制石斧】（石头×3 + 草×3）
   → 砍树得木材
   → 合成【木镐】（木材×3 + 石头×3）—— 石头来自沿途捡的小石块
   → 进矿区挖大石头（须镐）→ 得石头 stone
   → 回草原建【工作台】（木材×10）→ 解锁石斧 / 石镐 / 石剑 / 木甲
   → 攒石头 ×20 建【熔炉】
   → 进火山区挖煤 → 熔炉炼铁锭 → 铁制装备
```

### 3.11 视野流式加载 ✔（v0.3 未定义）

**需求："只渲染屏幕内的内容"。** 全图约 2400 个资源 + 敌人 + 掉落物如果全部常驻，节点数与 AI 开销都没必要。三方（资源 / 敌人 / 掉落物）共用同一份视野定义。

#### 3.11.1 视野定义（`ViewFrustum`）

| 参数 | 数值 | 说明 |
|------|------|------|
| 视野矩形来源 | 相机四角射线 × 玩家脚底平面求交 | 自动跟随俯角 / 朝向 / 缩放 |
| 资源 / 敌人 / 建筑装载半径 | **70 米** | 已盖住整个可见范围（可见地面约 33~59 米） |
| 掉落物装载半径 | **50 米** | 远小于此的掉落物没有意义 |
| 卸载滞回 | **24 米** | 超出「半径 + 24」才卸载 |
| 相机异常兜底 | 玩家周围 **45 米** | 取不到相机时（含无窗口测试环境） |
| 单次装配上限 | **16 个 / 帧** | 防瞬移时一帧造几百个节点卡顿 |

> 滞回是必须的：没有它，玩家在阈值上轻微移动会让同一批物体反复装卸，帧率出现规律性毛刺。

#### 3.11.2 资源：数据层 + 表现层

| 层 | 内容 | 数量 |
|----|------|------|
| 数据层 | 全图每条资源：ID / 坐标 / 状态 / 再生倒计时 | ~2400（全量，唯一存档源） |
| 表现层 | 只在视野内的实体节点 | ~60 |

**三条铁律：**
1. **卸载 = 退回对象池，绝不销毁节点** —— 再生倒计时靠节点活着
2. **采集中 / 被点击订单钉住的资源不卸载**
3. **未实例化的记录也要走再生倒计时** —— 否则"采完走远"= 该资源永久消失

#### 3.11.3 敌人与掉落物：挂起而非重建

- **挂起 = 把节点移出场景树（节点活着，血量 / 巡逻点 / 追击目标全保留），放回 = 加回场景树并设坐标**
- **绝不重建** —— 重建等于"远处的怪莫名其妙回满血"
- **玩家附近永不卸载**：敌人 30 米内（> 仇恨 14 / 开火 8）、掉落物 8 米内（> 拾取 1.2）始终常驻，否则会出现"追着你打的怪在视野边缘凭空消失"
- 节点被销毁（怪死 / 掉落物捡光）→ 清记录，否则存档会把死怪写回去

#### 3.11.4 建筑

建筑顺带做可见性剔除：隐藏时把碰撞层置 0，免得留下"看不见的墙"。

### 3.12 存档系统 ✔（v0.3 未定义）

#### 3.12.1 文件与槽位

| 项目 | 内容 |
|------|------|
| 存储位置 | `user://saves/slot_<id>.json`，一个存档一个文件 |
| 槽位数量 | **不限量** |
| 保存时机 | 暂停菜单手动保存；返回主菜单 / 退出 / 无槽时自动保存 |
| 槽位列表 | 主菜单直接读目录（无需索引文件） |

#### 3.12.2 存档内容（全量化）

| 段 | 内容 |
|----|------|
| meta | 存档名、天数、时刻、**地图种子**、**角色 id** |
| player | 位置、生命、电量、体温、饱食度、背包、装备三槽 |
| world | 天数 / 时刻、**全部资源状态**（含视野外的）、全部敌人、地面掉落物、相机 yaw/zoom |
| buildings | 全部建筑（含储物箱内容） |

#### 3.12.3 关键机制

- **地图种子必须存**：地图是运行时生成的。不存种子，读档会换一张随机地形，资源与建筑全部飘进海里。新开局摇种子、游戏内中途建槽沿用当前种子。
- **敌人按场景路径匹配**：存档里没有的路径 = 已被击杀 → 读档时删掉该节点；已处于死亡状态的不入档。
- **视野外实体也照存**：通过流式加载系统代理收集（视野外的实体不在场景树里，常规扫组方式扫不到，会被误判成"已击杀"而删除）。
- **读档清场**：重建建筑前先清光场景里已有的建筑节点与静态登记表；资源的过程态（采集中 / 再生中）归一化成"已采集"，避免读到没有计时器的中间状态而卡死。
- **装备直写槽位**：走正常装备流程会因背包满而丢装备，所以读档直接写槽。
- **向后兼容**：老存档没有敌人 / 掉落物字段时按"字段缺失"处理，而不是当成空数组清场。
- **◆ 已知缺口：`has_power`（是否装着动力核心）尚未入档** —— 现在读档按角色**开局默认值**重算，装了核心的角色读档会丢掉电量。做 `power_core` 本体时同批补上（见 3.1.3 / 6.2）。

> **✔ 电量行是"常驻占位"，不是动态增删（v0.8 修正）：** 状态栏**固定 4 行**，⚡ 行永远在 `VBoxContainer` 里 —— 亮起显示暖黄 `⚡ 100`，未激活显示灰色占位 `⚡ --`。
