### 1.3 分层架构（一句话概括）

```
                    ┌──────────── 表现层 ────────────┐
   UIManager（面板栈/懒创建）──> HUD / 9 个面板 / MapView 族
                    └─────────────────────────────────┘
                              ↑ 信号 / 静态单例
   ┌──────────── 逻辑层（全部为 class_name + static，无 autoload）────────────┐
   ResourceManager  ItemRegistry  CraftingSystem  BuildingSystem  SaveManager
   GraphicsConfig   ViewFrustum   WorldStreamer   DebugConfig    FilterSystem
   RespawnSystem    Slime/Drone   Building        ItemDrop       ...
   └────────────────────────────────────────────────────────────────────────┘
                              ↑ 数据/几何查询
   ┌──────────── 数据与场景层 ────────────┐
   MapGenerator3D（map_gen 组）→ MapGenerator（2D 数据引擎）
        ↑ task_system.gd（区域/地形权威表）
   project.godot（分辨率/输入/物理层）
```

**铁律**：核心系统一律 `class_name + static` 而**不用 autoload** —— 因为 `godot --script` 跑 headless 测试时不加载 autoload，否则测试全挂。跨文件只认全局类名与 `get_tree().get_nodes_in_group(...)`。

## 二、运行入口与场景装配

### 2.1 场景流

```
启动 → tscn/map.tscn（main_scene）
         │  主菜单在暂停菜单里通过 change_scene_to_file 反向跳转
         ├─ MapGenerator3D._ready()
         │     ① 建 TileContainer3D / FloorCollisionContainer
         │     ② 载入 MapGenerator（2D 数据引擎）并覆盖其 3 个子系统实例
         │     ③ 种子：SaveManager.pending_map_seed ≠ 0 → 复现同一张图
         │        （同时调全局 seed()，因为 layout/room_chain 里有裸 randf_range）
         │     ④ 8 步生成 → render_map_3d（MultiMesh）→ 建地板碰撞 → 传送玩家
         │     ⑤ 非读档时放测试储物箱；无条件生成测试敌人（东 9m Slime、西 9m Drone）
         └─ ResourceManager._ready()
               有 pending 读档 → apply_pending_load(self)
               否则 → spawn_initial_resources()（全图建"记录"，不建节点）+ 出生点起步簇
```

`tscn/main_menu.tscn` → `MainMenu(Control, main_menu_ui.gd)` + `UIManager(Node)`；  
`main_menu_ui._ready()` 会把 `UIManager.instance.esc_opens_pause` 置 `false`（主菜单无暂停概念），并在切场景前 `get_tree().paused = false`。

### 2.3 `tscn/player.tscn` 节点树（uid://drkoq7x6qkejo，318 行）

```

│                            collision_mask = 3（层1 玩家 + 层2 地面）
│   └── CollisionShape3D  CylinderShape3D(height=1.0, radius=0.33)  position y ≈ 0.5015
```

**节点分工（关键设计）**：玩家的"逻辑"散在 6 个平级子节点上 —— `Physics` 只管移动/战斗，`Vitals` 管三条生存状态，`ClickMover` 管鼠标点地/点资源寻路，`BuildPlacer` 管建造与建筑交互，`Equipment` 管装备槽，`Inventory` 管 20 格背包。**`Visual` 与 `Physics` 是兄弟节点**，所以 `physics.gd._process()` 每渲染帧把 `Visual.global_position` 插值同步到物理位置（消除抖动）。

## 四、模块详解

## 4.1 地图生成 `script/map/`


### `map_generator.gd`（1203 行，`extends Node2D`，无 class_name）

**定位**：纯数据引擎（不渲染），产出 `map_data: PackedByteArray`（`y*MAP_WIDTH+x` 索引）与任务坐标表。

**常量表**

| 常量                                    | 值                          | 含义                   |
| ------------------------------------- | -------------------------- | -------------------- |
| `TILE_SIZE`                           | 1                          | 1 瓦片 = 1 世界单位（≈一个身位） |
| `MAP_WIDTH` / `MAP_HEIGHT`            | 1600 / 1600                | 共 256 万瓦片            |
| `TILE_KEY_OFFSET` / `TILE_KEY_STRIDE` | 512 / 2048                 | 整数键编码（容纳负坐标）         |
| `ISLAND_RX` / `ISLAND_RY`             | 430.0 / 388.0              | 岛屿椭圆半轴               |
| `COAST_NOISE_AMPLITUDE`               | 0.13                       | 海岸线噪声幅度              |
| `REGION_WARP`                         | 70.0                       | 区域分界 domain warp 强度  |
| `MIN_START_REGION_RADIUS`             | 110.0                      | 出生区保护半径              |
| `REGION_BLEND_WIDTH`                  | 55.0                       | 群系过渡带宽               |
| `REGION_TIER_WEIGHT`                  | `{0:0.78, 1:0.85, 2:1.00}` | 各 tier 领地权重（<1 放大地盘） |

**生成流水线 `generate_map()` [161]**（8 步，按序调用）：

| 步骤 | 方法                          | 行号   | 算法要点                                                                                                                         |
| -- | --------------------------- | ---- | ---------------------------------------------------------------------------------------------------------------------------- |
| 0  | `init_map_data()`           | 180  | 建 `PackedByteArray(1600×1600)` 并 `fill(7)` 全海                                                                                |
| 1  | `layout_tasks()`            | 204  | 调 layout 力导向布局 → 归一化到瓦片坐标（中心 800,800；`target_rx=310`、`target_ry=280`），再 `clamp` 到 `[120,1480]`                               |
| 2  | `generate_room_chains()`    | 247  | 每任务算延伸方向 → 生成房间链 → `_place_room_no_overlap` 防重叠（半径从 `r-6` 每次 `-2` 缩到 24 为止）                                                  |
| 3  | `stamp_room_terrain()`      | 395  | 房间瓦片写入 `map_data`，相邻房间用加粗 Bresenham 连通                                                                                       |
| 4  | `fill_region_territories()` | 496  | **domain-warp 加权 Voronoi** 分配 6 区领地：`wx = fx + warp*70`；`d = (ddx²+ddy²)*w2`；`edge = √second − √best < 55` 时按概率采信次近地形（过渡带自然） |
| 5  | `create_task_link_roads()`  | 647  | TASK_LINKS 主路（`_creates_cycle` BFS 防环）+ 距离 < 500 的补充路（取最近 12 条，细线）                                                           |
| 6  | `build_island_base()`       | 812  | 5 阶段：DFS 标可达海洋→内海填沙滩(8)→噪声阈值 4 档量化铺滩（`MAX_BEACH_WIDTH=30` 轮，阈值 `0.125+t*0.75`）→二次 DFS 补内海→最外 16 圈强制海(7)                      |
| 7  | `render_map()`              | 1118 | （仅 2D 调试用）逐瓦片建 `ColorRect` + `draw_labels()`                                                                                 |

**其他关键函数**

- `draw_road(x1,y1,x2,y2,is_thin=false)` [1043]：插 `1~3` 个控制点近似贝塞尔，法向偏移 ±36，逐段 `_bresenham_line`。
- `_bresenham_line(x0,y0,x1,y1)` [1084]：写 `terrain = 0`（道路/泥地）。
- `_on_regenerate_pressed()` [1201]：重掷种子并整套重生成。

### `layout.gd`（431 行，`extends RefCounted`）

任务在岛上的**同心环布局**。内部类 `LayoutNode`（id/position/initial_angle/velocity/data/edges/is_anchored）、`LayoutEdge`（双向注册）。

- 常量：`SPRING_FORCE=100.0`（弹簧平衡距离，力 `(d-100)*0.3`）、`CHARGE_FORCE=8000.0`（库仑斥力 `-8000/d²`）、`DAMPING_FORCE=0.85`、`MAX_ITERATIONS=250`、`KINETIC_THRESHOLD=0.008`。
- `layout_tasks()` [310]：`tier_radii={0:10, 1:50, 2:110}`、`tier_offsets={0:0, 1:0, 2:TAU/12}`；草原（`is_start`）作为锚点；力导向只跑 **30 次**以保留同心结构。
- `normalize_to_tile_coords()` [390]：`tier_target_radius={0:0, 1:rx*0.52, 2:rx}`，全局 `stretch = randf_range(0.95,1.05)`，用 `node.initial_angle` 做极坐标（**保存初始角度是为了避免力导向后角度漂移导致 Marsh 塌陷**）。
- 注意：本文件用**全局** `randf_range()`（不走注入的 rng），所以 `map_generator_3d` 必须额外调全局 `seed()`。

### `room_chain.gd`（619 行，`extends RefCounted`）

每个区域生成"入口→中段→出口"链状房间。内部类 `RoomInstance`（task_id/role/template/center/radius/tiles）。

- `generate_chain_for_task()` [80]：半径按 tier —— Tier0 `30..40`、Tier1 `46..56`、Tier2 `60..72`；`spacing = radius*1.2`；沿 `direction` 排布 + 法向随机偏移 ±`radius*0.4`；每房间 `_generate_blob_tiles(..., 0.65, 0.9, 5)`。
- `_generate_blob_tiles()` [177]：`7~12` 个噪声种子（半径/相位随机）+ 分支（长度 0.7~~1.5 倍半径、宽 0.25~~0.70 倍、弯角 30°~90°）；用 `PackedByteArray` 网格扫描后合并。
- `_keep_largest_connected_component()` [364]：4 邻域 BFS 保留最大连通块（键 `(y+4096)<<16 | (x+4096)`）。
- `_is_in_noisy_circle()` [445]：三层正弦扰动 `sin(3θ+s)*0.11 + cos(5θ+1.7s)*0.07 + sin(7θ+2.3s)*0.04` 调制半径。
- `compute_chain_direction()` [558]：邻居方向平均；若指向地图中心则翻转（保证链往外延伸）。

### `mob/slime.gd`（876 行，`class_name Slime extends CharacterBody3D`）

**@export**：`max_health=30`、`move_speed=1.5`、`hate_range=8.0`、`stop_distance=1.0`、`attack_range=2.0`、`patrol_range=3.0`、`invincibility_time=0.5`、`attack_damage=5`、`attack_cooldown=1.0`、`gravity=20.0`、`drown_depth=-1.0`、`path_update_interval=0.4`、`waypoint_distance=0.6`、`obstacle_probe=0.9`。

**状态机**（`_state`）六态：`idle → walk → chase / hurt / drown / dead`，`_process_state_machine()` [263]。

- idle：1.5 s 后转 walk；玩家存活且在 8 m 内转 chase。
- walk：到点（<0.5）回 idle；仇恨内转 chase；否则走向巡逻点。
- chase：距离 `≤2.0` 且冷却结束 → `_attack_player`（播 attack）；`≤1.0` 停；超出 8 m 回 idle。
- 寻路：`_update_path()` [559] 在"空路径/超时/目标移动 >1.0 m"时重算；`_request_path()` [570] 调 `map_gen.find_world_path`。
- 绕障：`_avoid_obstacles()` [593] 依次试 `[0,45,−45,90,−90,135,−135]` 度偏转，`test_move` 探测 0.9 m。
- 落水：`_start_drowning()` [736] → `_drown()` [750] 0.3 s 后 `queue_free`（**不掉落**）。
- 死亡：`_die()` [764] 播 die、**掉 `slime_gel`×1**、1.0 s 后 `queue_free`。
- 存档：`get_save_data()` [357] = `{position, health}`；`apply_save_data()` [369] 复位所有运行态为 idle。
- 受击免疫：`invincibility_time=0.5`。

### `mob/drone/drone.gd`（586 行，`class_name Drone extends CharacterBody3D`）

**@export**：`max_health=20`、`move_speed=1.5`、`hate_range=14.0`、`combat_min=3.0`、`combat_max=8.0`、`attack_interval=2.0`、`attack_damage=5`、`projectile_speed=4.0`、`projectile_max_distance=12.0`、`fire_height=0.9`、`hitbox_radius=0.35`、`hover_height=1.5`、`battery_drop_chance=0.2`、`anchor_task_id="Rocky"`、`anchor_on_ready=true`。

- **`_ready()` 里 `collision_layer=0`、`collision_mask=0` → 完全无碰撞体积**（避免卡住玩家/被地板挡住）。
- **`_build_visual()` [498] 全部代码生成**：机身圆柱（top 0.25 / bottom 0.35 / h 0.35，metallic 0.7）、红眼球（emission `(1,0.15,0.1)`）、半透明旋翼盘（r 0.55），**外加 `Hitbox` Area3D（球半径 = `hitbox_radius` 0.35）** —— 玩家攻击靠这个 Area 命中。半径贴住机身最粗处（原 0.55 比外观胖一圈，手感"离着老远就被砍中"）。
- 状态：`idle` / `engage` / `hurt` / `dead`。悬停 `target_y = 1.5 + sin(_age*2)*0.25`（1.25~1.75），`lerpf(delta*3)`。
- 交战：`dist>8` 逼近、`dist<3` 后撤、**每 2~4 s 换横移方向**（速度 `move_speed*0.5`），`dist ≤ 8` 且冷却完 → `_fire()`。
- **`_fire()` [359] 平射**：枪口 = 机体前方 0.6 m，**高度强制为 `目标脚下 y + fire_height`**（不取机体高度 —— 无人机悬在 1.5 m、玩家碰撞体只到 1.0 m，从机体高度平射会从玩家头顶飞过）；弹幕的 `max_distance` 由 `projectile_max_distance` 同步。
- 死亡：`_die()` [391] 后以 `(0,-3,0)` 下坠 + 每秒缩小 2.0，`scale≤0.05` 时 `queue_free`；`randf() ≤ 0.2` 掉 `battery`。
- 锚定：`_anchor_to_region()` [409] 取 `get_task_world_position("Rocky")` 再 10~40 m 随机偏移，`_snap_to_land()` 螺旋找最近陆地。

### `mob/drone/drone_projectile.gd`（172 行，`class_name DroneProjectile`）

`speed=4.0`、`damage=5`、`max_distance=12.0`、`lifetime=6.0`（**兜底**，防 `speed=0` 时弹幕永不死）。`launch()` [82] = `(target-from)` 后**抹掉 `y` 再归一化** → 弹道**平行地面**、不带竖直分量（发射点多高就飞多高，所以枪口高度由 `drone.fire_height` 决定）。发光球 r=0.12；Area3D 球 r=0.3；命中玩家组 → `Physics.take_damage(5)` 后销毁；撞 StaticBody/CharacterBody 也销毁；累计飞行满 `max_distance` 米同样销毁。

### 地图视图族 `map_view.gd`（589 行，`class_name MapView`）+ 两个子类

**常量**：`TEX_SIZE=1600`、`BANDS_PER_FRAME=16`、`MIN_ZOOM=1.0`、`MAX_ZOOM=5.0`、`ZOOM_STEP=1.15`、`MARKER_INTERVAL=1.0`。  
**静态共享**（两个视图共用同一张底图，只生成一次）：`_s_gen` / `_s_tex: ImageTexture` / `_s_data: PackedByteArray` / `_s_row`。

**子类钩子**（默认实现）：

```gdscript
_map_rect()        -> Rect2          # 默认覆盖整个控件
_setup_view()                         # 定制
_cover_fit()       -> bool           # false=contain 留边；true=cover 铺满可裁
_rotates_with_view() -> bool         # 是否随相机旋转
_draw_before_map() / _draw_after_map()# 底图前后的自绘
_on_view_changed()                    # 视图变化回调
```

**坐标换算与旋转**

- `_px_per_world()` [287]：每世界单位像素数（两轴同一标量，**不能假设地图区正方形**）。
- `view_to_world(p) = _center + _rot2_inv(p − rect.center) / ppw`；`world2_to_view(w) = rect.center + _rot2((w − _center) * ppw)`。
- `_rot2(v) = (x·c − y·s, x·s + y·c)`，`_rot2_inv` 为逆；`_map_angle = atan2(fwd.x, fwd.z) + PI`，`fwd = -camera.global_transform.basis.z`（不依赖 camera_3d 私有 yaw）。
- `_clamp_view()`：`lim = max((world_size − span)*0.5, 0)`，中心夹在 `[−lim, lim]`。
- 滚轮缩放以**光标为锚**（缩放前后光标下世界点不动）；左键拖动；右键复位。
- 底图绘制：视口四角 → 世界 → **`_clip_halfplane()` Sutherland–Hodgman 裁剪到世界方形**（因为旋转无法用 `draw_texture_rect_region` 表达），UV 按公式 `(w.x/ws.x + 0.5, w.y/ws.y + 0.5)` 插值。
- 底图分帧：`_pump_texture()` [465] 每帧 16 行 → 1600 行约 **100 帧 ≈ 1.7 s**；`build_progress()` [243] 返回进度。
- 绘制顺序：`底色 → 底图/加载文字 → 描边 → _draw_after_map → 建筑标记(5px 黑底+3px 白块) → 玩家箭头`。

- 地形与区域是**一对一**关系（`get_task_by_terrain` 依 `task.terrain_type`）；沙滩通过虚拟区 `"Beach"` 与地形 8 对应。
- 破局链：`pebble → 石斧 → 树(需斧) → 木镐 → 大石/矿(需镐) → 熔炉 → 铁器`。

## 八、存档结构

### 8.1 文件布局

`user://saves/slot_<id>.json`（Tab 缩进），一档一文件，**槽位不限量**。


### 8.2 完整 JSON 结构

```jsonc
{
  "version": 1,
  "meta": {                       // 由 _make_meta() 生成；主菜单列表只读这一块
    "slot_id": 1, "name": "存档 1", "day": 3,
    "saved_at": "2026-09-13 04:56", "map_seed": 1234567
  },
  "player": {
    "position": {"x":0,"y":0,"z":0},   // Physics.global_position
    "health": 100,                      // Physics.current_health
    "power": 100.0,
    "temperature": 30.0,
    "hunger": 100.0,
    "inventory": { "max_slots": 20,
                   "items": [{"slot": 0, "item": {"item_id": "wood", "quantity": 12}}] },
    "equipment": { "weapon": "", "armor": "", "tool": "" }   // 只存 item_id
  },
  "world": {
    "day": 3, "hour": 14.5,             // day_night 组
    "resources": { ... ResourceManager.save_game() ... },     // {"version":1,"resources":[{instance_id,resource_id,position,state,regen_time_remaining}]}
    "enemies": [ {...敌人 get_save_data()..., "path": "Node3D/Slime"} ],
    "drops":   [ {"item_id":"slime_gel","count":1,"position":{...}} ],
    "camera":  { "yaw": 0.78, "zoom": 1.0 }
  },
  "buildings": [
    { "id": "storage_box", "position": {...},
      "storage": { "max_slots": 20, "items": [...] } }        // 仅储物箱有
  ]
}
```

### 8.3 读档顺序（`apply_pending_load` [205]）

```
1. 取 pending_load_slot 并置 -1
2. _read_slot(id) → 无 player 键则警告退出
3. _apply_world():
     a. day_night.set_time(hour, day)
     b. resource_manager.load_game(_normalize_resource_states(resources))
     c. has("enemies") → _apply_enemies（委托 WorldStreamer）
     d. has("drops")   → _apply_drops（委托 WorldStreamer）
     e. _apply_camera（无条件）
4. _apply_player():
     位置 → 生命(clampi 1..max + 刷 HUD 血条)
        → Vitals: set_power → 直写 temperature → set_hunger（走方法以发信号）
        → inventory.load_data() 后**必须 notify_all_slots()**
        → 装备用 set_slot_item 直写槽（不走 equip，因为读档时常满背包会静默丢装备）
5. _apply_buildings(): 先 find_children("*","Building") 清光 + BuildingSystem.clear()，再按档重建
```

### 8.4 容错设计（逐条都有实际代码）

| 场景                               | 处理                                                     |
| -------------------------------- | ------------------------------------------------------ |
| 文件不存在 / JSON 解析失败 / 非 Dictionary | `_read_slot` 返回 `{}`                                   |
| 老存档没有 `enemies`/`drops` 键        | 用 `has()` 判断，**不传空数组**（否则会触发清场，删掉新开局的敌人）               |
| 资源停在 TRANSITIONING/REGENERATING  | `_normalize_resource_states` 统一改 `HARVESTED`，避免读档后永久卡死 |
| 掉落物出生保护                          | 重放后覆盖 position 并 `set("_age", 10.0)` 跳过 0.4 s 保护       |
| 已击杀敌人                            | 按 `get_path_to` 路径匹配，**存档里没有的 `enemy` 节点直接删除**         |
| `_state == "dead"` 的敌人           | 不入档                                                    |
| 新开局被旧 pending 劫持                 | `create_slot` 每次清 `pending_load_slot`                  |
| meta-only 存档（只有名字没世界）            | `request_load` 返回 false，走正常开局生成                        |
| 无激活槽就保存                          | 现建槽且 `roll_new_seed=false`，沿用地形种子                      |
| 时间戳相同导致"继续游戏"进错档                 | `list_slots` 用 slot_id 兜底排序                            |

### 12.4 架构层面值得注意的约定（写代码时必须遵守，否则出诡异 bug）

1. **核心系统不用 autoload**，一律 `class_name + static`（`godot --script` 不加载 autoload）。
2. 新增 `class_name` 必须**手工补** `.godot/global_script_class_cache.cfg`（否则 headless 找不到类）。
3. `:=` 右侧必须是有类型表达式；右侧为 Variant 会让**整个脚本解析失败**，且静态 lint 只能部分捕获。
4. 枚举只能**末尾追加**（`.tres` 存的是数字）。
5. 对外暴露内部集合必须 `.duplicate()`。
6. **先 `add_child` 再设 `global_position`**，以及 **先入树再调依赖 `_ready` 的组件**（模板：`Building.spawn`、`ResourcePool.acquire`）。
7. 运行时 `new` 的控件**不能用 `set_anchors_preset`**（`_ready` 时是 0×0）→ 必须显式给 size/position；0×0 会导致悬停不到且点击穿透到 3D。
8. 世界点击的**三处 `_input`**（click_mover / camera_3d / build_placer）都必须有 `gui_get_hovered_control() == null` 守卫（`_input` 早于 GUI 处理）。
9. 卸载/挂起一律**复用节点**（对象池 or remove_child），绝不 `queue_free`，否则状态丢失。
10. 同一文件多处 Edit 必须**串行**（并行会静默丢改动）。
