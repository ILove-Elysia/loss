### 1.3 分层架构（一句话概括）

```
                    ┌──────────── 表现层 ────────────┐
   UIManager（面板栈/懒创建）──> HUD / 9 个面板 / MapView 族
                    └─────────────────────────────────┘
                              ↑ 信号 / 静态单例
   ┌──────────── 逻辑层（全部为 class_name + static，无 autoload）────────────┐
   ResourceManager  ItemRegistry  CraftingSystem  BuildingSystem  SaveManager
   GraphicsConfig   ViewFrustum   WorldStreamer   DebugConfig    FilterSystem
   RespawnSystem    Slime/Drone   Building        ItemDrop       ...
   └────────────────────────────────────────────────────────────────────────┘
                              ↑ 数据/几何查询
   ┌──────────── 数据与场景层 ────────────┐
   MapGenerator3D（map_gen 组）→ MapGenerator（2D 数据引擎）
        ↑ task_system.gd（区域/地形权威表）
   project.godot（分辨率/输入/物理层）
```

**铁律**：核心系统一律 `class_name + static` 而**不用 autoload** —— 因为 `godot --script` 跑 headless 测试时不加载 autoload，否则测试全挂。跨文件只认全局类名与 `get_tree().get_nodes_in_group(...)`。

## 二、运行入口与场景装配

### 2.1 场景流

```
启动 → tscn/map.tscn（main_scene）
         │  主菜单在暂停菜单里通过 change_scene_to_file 反向跳转
         ├─ MapGenerator3D._ready()
         │     ① 建 TileContainer3D / FloorCollisionContainer
         │     ② 载入 MapGenerator（2D 数据引擎）并覆盖其 3 个子系统实例
         │     ③ 种子：SaveManager.pending_map_seed ≠ 0 → 复现同一张图
         │        （同时调全局 seed()，因为 layout/room_chain 里有裸 randf_range）
         │     ④ 8 步生成 → render_map_3d（MultiMesh）→ 建地板碰撞 → 传送玩家
         │     ⑤ 非读档时放测试储物箱；无条件生成测试敌人（东 9m Slime、西 9m Drone）
         └─ ResourceManager._ready()
               有 pending 读档 → apply_pending_load(self)
               否则 → spawn_initial_resources()（全图建"记录"，不建节点）+ 出生点起步簇
```

`tscn/main_menu.tscn` → `MainMenu(Control, main_menu_ui.gd)` + `UIManager(Node)`；  
`main_menu_ui._ready()` 会把 `UIManager.instance.esc_opens_pause` 置 `false`（主菜单无暂停概念），并在切场景前 `get_tree().paused = false`。

### `map_generator.gd`（1203 行，`extends Node2D`，无 class_name）

**定位**：纯数据引擎（不渲染），产出 `map_data: PackedByteArray`（`y*MAP_WIDTH+x` 索引）与任务坐标表。

**常量表**

| 常量                                    | 值                          | 含义                   |
| ------------------------------------- | -------------------------- | -------------------- |
| `TILE_SIZE`                           | 1                          | 1 瓦片 = 1 世界单位（≈一个身位） |
| `MAP_WIDTH` / `MAP_HEIGHT`            | 1600 / 1600                | 共 256 万瓦片            |
| `TILE_KEY_OFFSET` / `TILE_KEY_STRIDE` | 512 / 2048                 | 整数键编码（容纳负坐标）         |
| `ISLAND_RX` / `ISLAND_RY`             | 430.0 / 388.0              | 岛屿椭圆半轴               |
| `COAST_NOISE_AMPLITUDE`               | 0.13                       | 海岸线噪声幅度              |
| `REGION_WARP`                         | 70.0                       | 区域分界 domain warp 强度  |
| `MIN_START_REGION_RADIUS`             | 110.0                      | 出生区保护半径              |
| `REGION_BLEND_WIDTH`                  | 55.0                       | 群系过渡带宽               |

**生成流水线 `generate_map()` [161]**（8 步，按序调用）：

| 步骤 | 方法                          | 行号   | 算法要点                                                                                                                         |
| -- | --------------------------- | ---- | ---------------------------------------------------------------------------------------------------------------------------- |
| 0  | `init_map_data()`           | 180  | 建 `PackedByteArray(1600×1600)` 并 `fill(7)` 全海                                                                                |
| 1  | `layout_tasks()`            | 204  | 调 layout 力导向布局 → 归一化到瓦片坐标（中心 800,800；`target_rx=310`、`target_ry=280`），再 `clamp` 到 `[120,1480]`                               |
| 2  | `generate_room_chains()`    | 247  | 每任务算延伸方向 → 生成房间链 → `_place_room_no_overlap` 防重叠（半径从 `r-6` 每次 `-2` 缩到 24 为止）                                                  |
| 3  | `stamp_room_terrain()`      | 395  | 房间瓦片写入 `map_data`，相邻房间用加粗 Bresenham 连通                                                                                       |
| 4  | `fill_region_territories()` | 496  | **domain-warp 加权 Voronoi** 分配 6 区领地：`wx = fx + warp*70`；`d = (ddx²+ddy²)*w2`；`edge = √second − √best < 55` 时按概率采信次近地形（过渡带自然） |

### `layout.gd`（431 行，`extends RefCounted`）

任务在岛上的**同心环布局**。内部类 `LayoutNode`（id/position/initial_angle/velocity/data/edges/is_anchored）、`LayoutEdge`（双向注册）。

### `vitals.gd`（762 行，`class_name PlayerVitals`，`extends Node`）

三条生存状态，`_process → _tick(delta)`，结算顺序 **温度 → 核心推进 → 饱食度 → 电量效果 → 推 HUD**。
人物自身的"电量"只有一条（自身电量，仅机器人）；核心那块电池挂在物品实例上（见 `core_instance.gd`），本脚本只负责**逐帧推进身上所有核心**（装备槽 + 背包）。

**数值体系（全部来自 @export 默认值）**

| 系统  | 区间                | 变化                                                                     | 阈值与联动                                                                                                 |
| --- | ----------------- | ---------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |

- signal：`power_changed` / **`core_power_changed`** / `temperature_changed` / `temperature_value_changed` / `hunger_changed`。

### `save/save_manager.gd`（`class_name SaveManager` 纯静态）

- `const SAVE_DIR="user://saves"`、`SAVE_VERSION=2`（v1 = 只有种子；v2 = 增加 `map` 段存地皮）；`static active_slot_id / active_slot_name / pending_load_slot / pending_map_seed`。
- 文件：`user://saves/slot_<id>.json`（`JSON.stringify(data, "\t")`，Tab 缩进）；顶层 `version / meta / map / player / world / buildings`。
- **`list_slots()`** 升序排序，时间戳相同用 slot_id 兜底（避免"继续游戏"进错档）。
- **`create_slot(name, roll_new_seed=true)`**：分配 id、设激活、清 pending、按需重摇种子（`maxi(1, rng.randi()%2147483647)`，避开 0），写 meta-only 文件；同时 `clear_pending_map_tiles()`（防"读档后回主菜单新建游戏"把上一档的岛带过来）。
- **`save_active_slot()`**：无激活槽则先建槽（`roll_new_seed=false` 沿用地形种子）。
- **`apply_pending_load(rm)`**：严格顺序 `_apply_world → _apply_player → _apply_buildings`。
- 读取方：`map_generator_3d`（`pending_map_seed` + `pending_map_tiles` / `has_pending_load`）、`resource_manager`（`apply_pending_load`）、`main_menu_ui`、`pause_menu_ui`。
- **地形快照（v2 新增）**：`_collect_map()` 从 `"map_gen"` 组取当前地皮 → `compress(DEFLATE)` + base64 存 `map.tiles`，另存 `w/h/size/tiles_hash`（SHA-256）；`_load_map_snapshot()` 在 `request_load()` 里解压回 `pending_map_tiles` 并校验哈希。**动机：种子只能复现"当年那套算法"算出的岛，改一行随机调用顺序就会整岛错位且不报错；存下地皮本身，生成算法随便改，老存档都还在。** 缺 `map` 段（v1 老档）自动退回按种子重算，并记一条日志。
- `sha256_hex(bytes)`：地形哈希的公开入口（也供生成器做"算法是否变过"的诊断比对）。
- **核心槽与电量**：装备四槽各存一份**物品实例字典**（`_collect_equip_slot`，空槽存 `""`），核心的电量与温度值随实例的 `core` 子字典一起进档；不再单独存 `player.has_power`（它是运行时计算属性）。**顺序要求**：`_apply_player` 里「装备恢复」必须排在「Vitals」之前；收尾还要无条件调 `equip.resync_core_state()`，否则读一个没装核心的档会把上一档的核心栏带过来。老档（装备格是纯 `item_id` 字符串）走 `_restore_equip_slot_by_id()` 兼容分支。

### 地图视图族 `map_view.gd`（589 行，`class_name MapView`）+ 两个子类

**常量**：`TEX_SIZE=1600`、`BANDS_PER_FRAME=16`、`MIN_ZOOM=1.0`、`MAX_ZOOM=5.0`、`ZOOM_STEP=1.15`、`MARKER_INTERVAL=1.0`。  
**静态共享**（两个视图共用同一张底图，只生成一次）：`_s_gen` / `_s_tex: ImageTexture` / `_s_data: PackedByteArray` / `_s_row`。

**子类钩子**（默认实现）：

```gdscript
_map_rect()        -> Rect2          # 默认覆盖整个控件
_setup_view()                         # 定制
_cover_fit()       -> bool           # false=contain 留边；true=cover 铺满可裁
_rotates_with_view() -> bool         # 是否随相机旋转
_draw_before_map() / _draw_after_map()# 底图前后的自绘
_on_view_changed()                    # 视图变化回调
```

**坐标换算与旋转**

- `_px_per_world()` [287]：每世界单位像素数（两轴同一标量，**不能假设地图区正方形**）。
- `view_to_world(p) = _center + _rot2_inv(p − rect.center) / ppw`；`world2_to_view(w) = rect.center + _rot2((w − _center) * ppw)`。
- `_rot2(v) = (x·c − y·s, x·s + y·c)`，`_rot2_inv` 为逆；`_map_angle = atan2(fwd.x, fwd.z) + PI`，`fwd = -camera.global_transform.basis.z`（不依赖 camera_3d 私有 yaw）。
- `_clamp_view()`：`lim = max((world_size − span)*0.5, 0)`，中心夹在 `[−lim, lim]`。
- 滚轮缩放以**光标为锚**（缩放前后光标下世界点不动）；左键拖动；右键复位。
- 底图绘制：视口四角 → 世界 → **`_clip_halfplane()` Sutherland–Hodgman 裁剪到世界方形**（因为旋转无法用 `draw_texture_rect_region` 表达），UV 按公式 `(w.x/ws.x + 0.5, w.y/ws.y + 0.5)` 插值。
- 底图分帧：`_pump_texture()` [465] 每帧 16 行 → 1600 行约 **100 帧 ≈ 1.7 s**；`build_progress()` [243] 返回进度。
- 绘制顺序：`底色 → 底图/加载文字 → 描边 → _draw_after_map → 建筑标记(5px 黑底+3px 白块) → 玩家箭头`。

### `BossSandwormBase` 的状态机（要点）

```
DORMANT ──玩家进触发圈并停留 trigger_dwell──> EMERGING ──emerge_time──> CHASE
CHASE ──决策点选招──> TELEGRAPH ──strike─> STRIKE ──recover_time──> RECOVER ──> 回 CHASE 再决策
CHASE/招式三段 ──玩家离开领地(距巢穴>leash_radius 持续 leash_time) 或 玩家 died ──> RETREAT ──回巢──> 回满血 → DORMANT
take_damage 内血量扣到 ≤0 ──> FALLEN（保底 1 血 + **永久**无敌）──逃回巢穴──> GONE（写 WorldState 旗标）
```

- **决策点**＝"刚进攻击距离"或"每次后摇结束"：按血量选表 → 取**轮转到的**那一招。
  容错：轮到的招**够不着**（> `max_range`）⇒ 不出招、回 `CHASE` **继续潜行逼近**（指针不动，追进射程再放，
  即"潜近再放"）；在 CD 或太近（< `min_range`）⇒ 顺延到下一条；一圈都轮不到 ⇒ 继续贴身追。
  **任何情况都不空放、不发呆。**
  ⚠ 这条规则的副作用就是**"交战距离"由表头决定**：两张表的表头（① 与 ④）都是**近身招**
  （`max_range` = 1.0 / 0.5，2026-09-27 用户给定）⇒ **1 m 之外它一招都不出、只会闷头追**；
  ②③ 的远射程（15 / 20）只有在指针被表头**推进过**之后才轮得到（＝"先贴身挨一下、再跑远"）。
  ⚠ 要让"按距离分层出招"真正成立，得把"够不着 ⇒ 返回 `null`"改成"够不着 ⇒ **顺延尝试下一招**"
  —— 属于机制改动，**已列入待拍板，没有擅自动**。
  ⚠ 另一个旋钮是**逼近速度**（2026-09-27 补）：`_movement_speed()` 在 `CHASE` 里按
  `upcoming_attack()`（只读预判"接下来轮到谁"、**不改任何指针**，跳过在 CD 里的）把移速顶到那一招的
  `approach_speed`（0 ⇒ 用 `chase_speed`）⇒ ④ 配 7.0 就成了"**锁定你就提速扑过来**"，
  而一起手就离开 `CHASE`、速度自动回落（＝"放完恢复原来的速度"**不需要额外计时器**）。
  见下面 ④ 与回归用例 20。
- **顺序轮转**（2026-09-26 从"优先级轮询"改过来）：老版永远优先第 1 招，玩家一拉开距离就只可能见到远程招；
  新版①一定最先出、②紧跟其后 —— 顺序本身是留给玩家**背板**的。指针是 `_rotation_index`；
  **换表时归零**（`_sync_rotation_with_phase()`）：表 2 的顺序写作"④①②③"，不归零就会从表 2 中间某招续下去、"4123"读不出来。
- **相位切换是隐式锁存**：没有 `_phase` 字段，`_current_table()` 只在决策点被调用 ⇒ 招式播到一半绝不换表。
  分界线是 `@export phase_line`（默认 0.5），`_current_table()` 与 `current_phase()` 共用它。
- **`RETREAT` 与 `FALLEN` 共用** `_process_going_home()`，走到巢穴才分头（一个回满血回 DORMANT，一个进 GONE）。
- 同帧多段伤害的防线在 `take_damage` **第一行**（`_untouchable`）——玩家一次挥砍 `intersect_shape(..., 10)` 能命中多个碰撞体。
- ⚠ **扣血会「同步重入」状态机 —— 这是本模块最阴的一处**：`_apply_attack_damage()` 里的 `body.take_damage()`
  可能把玩家打死 ⇒ 玩家**同步**发 `died` ⇒ `_on_player_died()` ⇒ `_start_retreat()` ⇒ `_set_state(RETREAT)`
  ⇒ 依「离开招式三段就丢掉当前招」把 `_attack` 置 null，**而扣血函数还没返回**。写法要求：
  ① 进 `_apply_attack_damage()` 先取局部引用 `var attack: BossSandwormAttack = _attack`，扣血之后**只用局部变量**，
  绝不再回头读 `_attack`；② 调用方 `_process_attack()` 在调完之后必须重新确认（`if _attack == null: return`），

  就是这条：一次死亡连报两条 `Invalid access to property ... on a base object of type 'Nil'`
  （先 `attack_id`、紧接着是调用方那行的 `strike_time`）。`test/boss_state_test.gd` 用例 13 专门回归它。
- **不进 `"enemy"` 组，用 `"boss"` 组**：`map_generator_3d._place_enemies()` 会把 `enemy` 组全搬到丛林区；`save_manager`/`world_streamer` 对 `enemy` 组用的是"存档里没有＝已击杀"，对 Boss 是反的。
- 调试专用（**正式逻辑别用**）：`debug_wake()` / `debug_damage_to()` / `debug_set_all_cooldowns()`。
  ⚠ `debug_set_all_cooldowns()` **必须在没有招式正处三段里时调用**：正在播的那一招走到 RECOVER 结束会把
  自己的 `cooldown` 写回去（如 `sand_spit` 的 5 s），覆盖掉刚设的 30 s ⇒ 该招提前解禁。2026-09-25 踩过。

### 受击窗口：**只有露出地面的那几段能被打**（2026-09-26）

沙虫平时在地下潜行（追击 / 逃走），只在**冒头出招**时打开受击碰撞体。判据只有一处 ——
`BossSandwormBase._is_surfaced()`；碰撞层开关与占位美术的埋深都从它派生（同一个口径，
才不会出现"看着在地上却打不到"这种自相矛盾）：

| 状态 | 露头？ | 受击碰撞体 |
| --- | --- | --- |
| `TELEGRAPH`（冒头前摇：①②，`surfaces_in_telegraph = true`） | 是 | **开** |
| `TELEGRAPH`（地下筹备：③流沙 / ④突袭，`= false`） | 否 | **关** |
| `STRIKE` / `RECOVER` | 是 | **开** |
| `CHASE` / `RETREAT` / `FALLEN`（潜地移动） | 否 | 关（只露一截背脊，`travel_depth`） |
| `DORMANT` / `EMERGING` / `GONE` | 否 | 关 |

- 开关切的是 **`collision_layer`（8 ↔ 0）**、不是 `collision_mask`：mask 保持 2 ⇒ 它照样站在地面上；
  layer 置 0 ⇒ 玩家挥砍的 `intersect_shape`（mask = 全部层）**查不到它** ⇒ "打不到"是字面意义的打不到。
  顺带没有"看不见的墙"（埋着时玩家能从它上面走过去）。工程内同款做法见 `resource_manager.gd` 隐藏建筑那段。
- **受击体尺寸 = `CylinderShape3D(r0.8, h2.0)`、中心 y = 1.0**（2026-09-26 从 r1.3/h2.4 收小）：
  玩家的有效攻击距离 = `attack_range`(2.0) **+ 受击体半径** ⇒ 原值算出来 **3.3 m**，
  比史莱姆（2.0 + 0.335 ≈ 2.34 m）多出 1 m，实机感受是"离很远就能打到"（用户反馈）
  ⇒ 收到 **≈ 2.8 m**。**占位模型不动**（用户拍板）：所以能打到的范围比看到的轮廓细一圈。
  这条数值由回归用例 19 钉住（`radius <= 0.85`）。
  ⚠ 另一个理由别忘：`collision_layer = 8` **不在玩家的 `collision_mask`(3) 里** ⇒
  这个碰撞体**只当受击体用**，不挡路、不影响走位，收小它没有物理副作用。
- `take_damage()` 里还有第二道门（`_is_surfaced()`）："**本招**是否在地下筹备"是运行时状态，
  静态谓词 `BossSandwormState.can_be_hurt(state)` 表达不了它，只能表达"`CHASE` 一律不可受伤"这一层。
- ⚠ **`debug_damage_to()` 故意绕过受击窗口**（走 `_apply_damage()`，不走 `take_damage()`）：
  否则调试时"摆血量"会变成要看沙虫脸色的运气活。濒死/退场（`_untouchable`）那条仍然拦。
- 副作用：**玩家的输出窗口只剩每招的判定 + 后摇**（约 1.4 ～ 2.1 s/招）。测试里想直接打血，
  必须先等 `collision_layer != 0`（用例 3 就是这么写的）。

- **"钉死"还是"跟着走"由 `aims_at_player` 决定**（与判定原点 `_damage_origin()` 同一口径）：
  落点在玩家身上的招（③流沙）**钉在施放那一刻的落点** —— 跟着跑就等于"永远罩着你"、把"跑出圈"这条活路取消掉；
  判定原点在它自己的招（①④）**每帧跟到它当前的位置** —— 否则④一边在地下冲刺、预警片却停在起手的地方，
  玩家看到的是废信息。所以④的长条是**追着它一起跑**的，而那是它前摇（0.35 s，且埋在地下）里唯一读得到的信息。
- 形状都是**手工拼的水平网格**：扇形 = 平面三角扇（`_build_arc_mesh()`：圆心 + 圆弧采样点，按 (半径, 张角) 缓存）、
  长条矩形 = 两个三角形（`_build_rect_mesh()`，按 (长度, 宽度) 缓存）；材质关掉背面剔除、走 UNSHADED（与其它占位网格一致）。
- 越接近爆发越暗、alpha 越高（`_update_zone_fx()`）—— 顺带给出"还剩多久"的读数。
- **判定段一开始就收起**（`_enter_strike()` → `_hide_zone()`），不会残留到出完招。

### 占位外观：**必须 UNSHADED**（2026-09-26）

沙虫预制体与测试场地的地面 / 巢穴土堆都是**纯色占位网格**，它们的材质一律
`BaseMaterial3D.SHADING_MODE_UNSHADED`。这不是审美选择，是为了躲**过曝**：

| 项 | 值 | 后果 |
| --- | --- | --- |
| `map.tscn` 的环境光 | `ambient_light_color(0.83) × ambient_light_energy(9.0)` | 受光面被整体抬亮约 **2.2 倍** |
| 打爆阈值 | albedo 亮过 **0.45** | 直接被**打成纯白**（现工程里没做 tonemap） |
| 地形瓦片色（草原 / 沙滩 / 沙地） | 0.70,0.85,0.50 / 0.98,0.92,0.68 / 0.95,0.88,0.45 | **全在阈值以上** |

于是沙虫和地面一起变白糊成一片，连"前摇变红 / 濒死变灰"这些**状态信号**也一起白掉。
**全工程的地形与海面本来就一律 UNSHADED**（`map_generator_3d.gd` 的 `_create_tile_multimesh()`），
所以这不是特例 —— **往后新增任何 3D 网格都照这个来**。占位件尤其别漏 `material_override`：
漏了就用引擎默认的**白色受光**材质，又是一块白（`Visual/Jaw` 原先就是这么漏的）。
`BossSandwormBase._setup_placeholder_material()` 现在会遍历 `Visual` 下**所有** `MeshInstance3D` 逐个赋材质，
并按名字把 `Jaw` 换成暗一档的（`jaw_darken`），免得以后加了新零件又漏。

配色还有一条：**体色要压暗一档**才能在**任何**地形上都看出轮廓 —— 原体色 (0.82,0.70,0.42)
与沙地 / 沙滩瓦片色几乎一样，就算不过曝也糊在一起。现在 `body_color` = (0.58,0.45,0.26) 深沙褐。
这些色值走 UNSHADED ⇒ **就是"屏幕上直接看到什么"**，挑色时不用再心算光照会打亮多少。

**这类"颜色不对 / 看不清"的问题要出图取证**（headless 渲染不出画面，必须开窗口）：
隔离副本 + `--script <截图脚本> --quit-after N`，脚本 `extends SceneTree`、`root.add_child(场景)`、

（比肉眼看图更硬）。⚠ `_initialize()` 里只要报一次错就永远走不到 `quit()`，进程会挂着不退

### 6.2 玩家动画（`tscn/player.tscn` 内 `SpriteFrames_hl5qd`）

贴图：`res://art/player/adventurer/char_blue.png`（**448×392**，8 列 × 7 行，单帧 **56×56**）。  
`AnimatedSprite3D` 位置 `(0, 0.75, 0)`，`scale = (-2.6434, -2.6434, 1)`，`flip_h`/`flip_v = true`。

**左右翻转约定（改朝向系统前必读）**：这个节点的 `scale` 是**负数**，等价于"绕 Z 转 180°"；它和 `flip_v = true` 两次竖直/水平镜像互相抵消后，**净剩一次水平镜像**。再叠上 `SpriteFacing` 产生的朝向（与引擎 `billboard` 一致，**未镜像**，局部 +X = 相机右方向），结果是：

| `flip_h` | 屏幕上 | 对应 `facing_left` |
| -------- | ------ | ------------------ |
| `true`   | 朝**右** | `false`（往右走）  |
| `false`  | 朝**左** | `true`（往左走）   |

所以 `physics.gd` 里是 **`spr.flip_h = not facing_left`**。`slime.gd` 的 `Sprite` 是干净的单位变换、没有那次内置镜像，符号**相反**（`flip_h = _facing_left`），两边**不能互相照抄**。
2026-09-22 把朝向从 `look_at(相机方向)`（镜像朝向）换成 `SpriteFacing`（未镜像朝向）时漏了这一步，表现就是"人物左右方向反了"。`test/sprite_facing_check.py` 的第 3、4 项常驻核对这两件事。

| 动画       | 帧数 | speed | loop | 贴图行起点 (x,y)   | 用途                |
| -------- | -- | ----- | ---- | ------------- | ----------------- |
| `idle`   | 6  | 8.0   | ✔    | (0, 0)        | 待机                |
| `walk`   | 8  | 8.0   | ✔    | (0, 114)      | 行走（单帧 56×57）      |
| `attack` | 6  | 8.0   | ✘    | (0, 56)       | 攻击（**第 2 帧结算伤害**） |
| `harvest`| 3  | 5.0   | ✘    | (56→0→56, 168)| 砍树 / 挖矿（**不结算伤害**） |
| `hurt`   | 8  | 9.0   | ✘    | (0, 280)      | 受击                |
| `die`    | 4  | 7.0   | ✘    | (0, 336)      | 死亡                |

**`harvest`（2026-09-23 新增）**：采集时播的作业动作，帧取自精灵表**第 4 行 y=168** 的「直立抬臂 → 俯身下劈」（`Rect2(56,168,56,56)` → `Rect2(0,168,56,56)` → 再回抬臂，3 帧）。它**不再借用 `attack`**——`attack` 带白色剑光弧，砍树时播它出戏，而且会让玩家以为攻击判定生效了。

代码侧由 `physics.gd` 的 `is_working` 标志位护航（`is_attacking` 只管战斗，两者独立）：
- `play_harvest_action()` 置位并播 `harvest`；同一下作业尚未播完时重复调用直接忽略（否则动画永远停在第 1 帧）；
- `_update_animation()` 里作业中**原地不动就 return**（不加这道闸，本帧末尾就会把 harvest 切回 idle，玩家只看到闪一下）、**一移动就让位 walk**；
- `_on_attack_animation_finished()` 的 `harvest` 分支清零并回 idle；`perform_attack()` / `_on_death()` / `revive()` 各清一次。

常驻核对：`test/player_anim_check.py`（帧区越界、六动画齐全、harvest 只能取自劳作行、`is_working` 六处配对、三张角色表轮廓一致）。

`physics.gd` 还会设 `texture_filter = NEAREST(0)` 与 `alpha_antialiasing = DISABLED(0)` 保像素风清晰。

## 八、存档结构

### 8.1 文件布局

`user://saves/slot_<id>.json`（Tab 缩进），一档一文件，**槽位不限量**。


### 8.2 完整 JSON 结构

```jsonc
{
  "version": 1,
  "meta": {                       // 由 _make_meta() 生成；主菜单列表只读这一块
    "slot_id": 1, "name": "存档 1", "day": 3,
    "saved_at": "2026-09-13 04:56", "map_seed": 1234567
  },
  "player": {
    "position": {"x":0,"y":0,"z":0},   // Physics.global_position
    "health": 100,                      // Physics.current_health
    "power": 100.0,                     // **自身电量**（只有机器人有意义）
    "temperature": 30.0,
    "hunger": 100.0,
    "inventory": { "max_slots": 20,
                   "items": [{"slot": 0, "item": {"item_id": "power_core", "quantity": 1,
                                                  "core": {"core_id":"power_core","builtin":false,
                                                           "power":73.5,"temperature_value":410.0}}}] },
    "equipment": { "weapon": "", "armor": "", "tool": "",
                   "core": {"item_id":"power_core","quantity":1,
                            "core":{"core_id":"power_core","builtin":false,
                                    "power":40.0,"temperature_value":500.0}} }
    // 四槽各存**物品实例字典**（ItemInstance.to_dict），空槽为 ""。
    // 核心自带的电量 / 温度值就在 "core" 子字典里 ⇒ 拆下重装不会回满。
    // 老档（装备格是纯 item_id 字符串）走兼容分支还原。
    // 已不再存 "has_power"（它是运行时计算属性）。
  },
  "world": {
    "day": 3, "hour": 14.5,             // day_night 组
    "resources": { ... ResourceManager.save_game() ... },     // {"version":1,"resources":[{instance_id,resource_id,position,state,regen_time_remaining}]}
    "enemies": [ {...敌人 get_save_data()..., "path": "Node3D/Slime"} ],
    "drops":   [ {"item_id":"slime_gel","count":1,"position":{...}},
                 {"item_id":"power_core","count":1,"position":{...},
                  "core":{"core_id":"power_core","builtin":false,"power":88.0,"temperature_value":300.0}} ],
    "camera":  { "yaw": 0.78, "zoom": 1.0 }
  },
  "buildings": [
    { "id": "storage_box", "position": {...},
      "storage": { "max_slots": 20, "items": [...] } }        // 仅储物箱有
  ]
}
```

### 8.3 读档顺序（`apply_pending_load` [205]）

```
1. 取 pending_load_slot 并置 -1
2. _read_slot(id) → 无 player 键则警告退出
3. _apply_world():
     a. day_night.set_time(hour, day)
     b. resource_manager.load_game(_normalize_resource_states(resources))
     c. has("enemies") → _apply_enemies（委托 WorldStreamer）
     d. has("drops")   → _apply_drops（委托 WorldStreamer）
     e. _apply_camera（无条件）
4. _apply_player():
     位置 → 生命(clampi 1..max + 刷 HUD 血条)
        → inventory.load_data() 后**必须 notify_all_slots()**
        → 装备恢复：四槽各自 ItemInstance.from_dict → set_slot_instance（不走 equip，
          因为读档时常满背包会静默丢装备）；老档纯 item_id → _restore_equip_slot_by_id()
          → 收尾**无条件**调 equip.resync_core_state()：循环只处理"槽里有东西"的情况，
            读没装核心的档会整段跳过，不补这一下就会把上一档的「核心」栏带过来
        → Vitals: set_power（只恢复自身电量；**核心电量随核心实例走，不在这里恢复**）
          → 直写 temperature → set_hunger（走方法以发信号）
        ⚠ 装备恢复仍必须排在 Vitals 之前（槽里装上核心会触发 on_core_changed 推 HUD）
5. _apply_buildings(): 先 find_children("*","Building") 清光 + BuildingSystem.clear()，再按档重建
```

### 8.4 容错设计（逐条都有实际代码）

| 场景                               | 处理                                                     |
| -------------------------------- | ------------------------------------------------------ |
| 文件不存在 / JSON 解析失败 / 非 Dictionary | `_read_slot` 返回 `{}`                                   |
| 老存档没有 `enemies`/`drops` 键        | 用 `has()` 判断，**不传空数组**（否则会触发清场，删掉新开局的敌人）               |
| 资源停在 TRANSITIONING/REGENERATING  | `_normalize_resource_states` 统一改 `HARVESTED`，避免读档后永久卡死 |
| 掉落物出生保护                          | 重放后覆盖 position 并 `set("_age", 10.0)` 跳过 0.4 s 保护       |
| 已击杀敌人                            | 按 `get_path_to` 路径匹配，**存档里没有的 `enemy` 节点直接删除**         |
| `_state == "dead"` 的敌人           | 不入档                                                    |
| 新开局被旧 pending 劫持                 | `create_slot` 每次清 `pending_load_slot`                  |
| meta-only 存档（只有名字没世界）            | `request_load` 返回 false，走正常开局生成                        |
| 无激活槽就保存                          | 现建槽且 `roll_new_seed=false`，沿用地形种子                      |
| 时间戳相同导致"继续游戏"进错档                 | `list_slots` 用 slot_id 兜底排序                            |


### 10.3 Python 检查工具（无需 Godot 二进制）

四个脚本组成一套「改完资产就跑一遍」的自检流水线，退出码非 0 即有 error。

**`test/gd_static_lint.py`（447 行，6 项检查）**

1. **缩进跳变**（某行比上一行多缩进 ≥2 级；豁免括号未闭合续行与 `\` 续行）
2. **括号平衡**（先摘字符串再切注释）
3. **不可见空白字符**（NBSP / 全角空格 / 零宽空格 / BOM / EN·EM·FIGURE·THIN·HAIR·NARROW NBSP / MMSP）
4. **`class_name` 缓存一致性**（脚本声明的类名必须在 `.godot/global_script_class_cache.cfg`；反向校验缓存里的 `res://script/` 路径仍存在）
5. **Vector2/Vector3 成员误用**（`Vector2.x.z` / `Vector3.x.w`）
6. **`:=` 类型推断失败**（右侧最外层是 `.get()`/`.call()`、确认返回 Variant 的内置 API、或项目内无返回类型标注的函数）—— 这一项很关键：`:=` 右侧为 Variant 会导致**整个脚本解析失败**（不只是警告）

**`test/check_data_refs.py`（289 行）**

全工程 `res://` 引用存在性校验：扫 `.tres` / `.tscn` / `.res` / `.gd`，逐条判断引用目标是否存在（含二进制 `.res` 内部的字符串引用），另检查 `art/` 下图片是否缺 `.import`。自带跳过逻辑：忽略 `res://.godot/`（引擎生成物）与任何自带 `project.godot` 的嵌套工程。
数据层另查 7 项：item 注册表、`icon` 字段、`crafting_system` 产物/材料、`resource_registry` 的 id 与掉落物、`task_system.REGION_RESOURCE_MAP`、`_TEST_BOX_CONTENTS`。

**`test/find_orphans.py`（253 行）**

未被引用文件扫描。建 `res://` + `uid://` 引用图，找出既无字面量引用、`class_name` 也无人使用的文件，按目录分层汇总（`--list` 出明细）。要点：`.import` / `.uid` 属附属文件须排除出引用提取，`.md` 不计为引用来源。**孤岛 ≠ 可删**，需人工分层。

**`test/fix_import_paths.py`（70 行）**

批量移动资源后，同步 `.import` 内的 `source_file` 字段。不做的话 Godot 会把所有被移动的贴图当新文件全量重新导入。

**`test/make_ore_icons.py`（298 行）**：用 Python 标准库（`struct` / `zlib`）手写 PNG，生成矿物链图标并附带 `.import` 文件。

**`test/verify_save_map.py`（160 行）**：独立校验存档 `map` 段（DEFLATE + base64 地形快照）能否正确解压还原。

### 12.4 架构层面值得注意的约定（写代码时必须遵守，否则出诡异 bug）

1. **核心系统不用 autoload**，一律 `class_name + static`（`godot --script` 不加载 autoload）。
2. 新增 `class_name` 必须**手工补** `.godot/global_script_class_cache.cfg`（否则 headless 找不到类）。
3. `:=` 右侧必须是有类型表达式；右侧为 Variant 会让**整个脚本解析失败**，且静态 lint 只能部分捕获。
4. 枚举只能**末尾追加**（`.tres` 存的是数字）。
5. 对外暴露内部集合必须 `.duplicate()`。
6. **先 `add_child` 再设 `global_position`**，以及 **先入树再调依赖 `_ready` 的组件**（模板：`Building.spawn`、`ResourcePool.acquire`）。
7. 运行时 `new` 的控件**不能用 `set_anchors_preset`**（`_ready` 时是 0×0）→ 必须显式给 size/position；0×0 会导致悬停不到且点击穿透到 3D。
8. 世界点击的**三处 `_input`**（click_mover / camera_3d / build_placer）都必须有 `gui_get_hovered_control() == null` 守卫（`_input` 早于 GUI 处理）。
9. 卸载/挂起一律**复用节点**（对象池 or remove_child），绝不 `queue_free`，否则状态丢失。
10. 同一文件多处 Edit 必须**串行**（并行会静默丢改动）。
