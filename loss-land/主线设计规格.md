## 1. Boss 状态机骨架

### 1.1 先看现状：现有敌人是怎么写的

| | `slime.gd` | `drone.gd` |
|---|---|---|
| 基类 | `class_name Slime extends CharacterBody3D` | `class_name Drone extends CharacterBody3D` |
| 状态表示 | `var _state: String = "idle"`（第 119 行） | `var _state: String = "idle"`（第 117 行） |
| 派发 | `_process_state_machine()` 里 `match _state:`（281 行） | 同套路（219 行），状态是 `idle`/`engage` |
| 每个状态 | `_process_idle/_process_walk/_process_chase(delta)` | 同上 |
| 规模 | 41 个函数 / 876 行 | 相近 |

**两个敌人各写各的，没有公共基类，也没有可复用的状态机。** 全工程 `grep -i boss` **零命中** —— `script/ai/enemy/boss/` 是个空目录，Boss 一切从零。

另有一个可借鉴的现成件：`script/resources/component/resource_state_machine.gd`（`class_name ResourceStateMachine extends Node`），它的形状是**对的**：

```
change_state(new) / _enter_state() / _exit_state() / signal state_changed / get_state_data(key) / set_state_data(key, v)
```

但它把枚举写死成 `ResourceState.State`，**不能直接拿来给敌人用**；本规格照抄它的形状、换成 Boss 自己的枚举。

> **结论**：不要继续沿"String `_state` + `match`"这条老路写三条 Boss 线（那会是 3 × 900 行）。新起一层 `BossSandwormBase`，招式数据化，状态显式化。

### 1.2 状态表（骨架的核心）

| 状态 | 含义 | 进入条件 | 离开条件 | 可受伤 | 存进存档 |
|---|---|---|---|---|---|
| `DORMANT` | 未触发（在巢穴里/在树上） | 初始 / 脱战回到巢穴 | 玩家进入触发圈并停留够 | 否 | 是（= 还没被击退） |
| `EMERGING` | 登场（钻出沙面 / 降落） | 触发成立 | 登场动画播完 | 否 | 否（瞬时） |
| `CHASE` | 追击玩家（**在土里**，只露一截背脊） | 登场完 / 玩家回到仇恨圈内 | 进入攻击距离 / 玩家跑出脱战半径 | **否**（潜地） | 是 |
| `TELEGRAPH` | 前摇（**给玩家躲的窗口**） | 轮转轮到的那招够得着且不在 CD | 前摇计时结束 | **露头才可**（①②露头 ⇒ 是；③④在地下筹备 ⇒ 否） | 否 |
| `STRIKE` | 招式生效（判定伤害） | 前摇结束 | 生效帧过去 | 是 | 否 |
| `RECOVER` | 后摇（硬直，玩家的输出窗口） | 生效完 | 后摇计时结束 | 是 | 否 |
| `RETREAT` | **脱战逃走**（玩家跑远） | 玩家距离 > 脱战半径，持续够久 | 回到巢穴/树 → 回满血回 `DORMANT` | 否 | 否（**不写世界状态**） |
| `FALLEN` | **濒死逃走**（保留 1 点生命） | 受击后血量将 ≤ 0 | 走完逃走路径 → `GONE` | 否（永久无敌） | 是（一次性） |
| `GONE` | 已退场（场地已变） | `FALLEN` 抵达终点 | —（实例不再复用） | 否 | 是（写世界状态） |

**四条必须在代码里用注释钉死的规则：**

1. **没有 `dead` 状态。** 这套状态机里不存在"死亡并 `queue_free`"。Boss 的终点是 `GONE`（退场），不是死。任何从现成敌人代码里抄来的 `_die()` / `queue_free()` 逻辑都要删掉。
2. **`RETREAT` 与 `FALLEN` 是两件不同的事，不能合并。** 前者是"玩家跑了"，可重复发生、回满血、**不推进世界**；后者是"打到 1 血"、一次性、**推进世界 + 触发场地变化**。`slime.gd` 把"无敌"只做成计时器（`_is_invincible` + `invincibility_time = 0.5`），Boss 的 `FALLEN` 需要的是**永久的**不可伤害标志。
3. **Boss 实例的存活 ≠ 世界进度。** 沙虫线的第二阶段是**另一只** Boss（被改造成机械沙虫的那只），不是同一实例换皮。所以世界推进记在 `WorldState` 的旗标上（见 1.6），`GONE` 之后**原实例可以移除**，第二次战斗是另一个 `boss_id` 的新实例。
4. **受击窗口 = "露出地面"的那一段。** 沙虫平时在地下潜行（`CHASE` / `RETREAT` / `FALLEN`），只有**冒头出招**时才打开受击碰撞体；③流沙陷落 / ④潜行突袭 连前摇都还在地底（在地下筹备 / 高速突进），所以它俩的窗口只有判定 + 后摇。判据集中在 `BossSandwormBase._is_surfaced()` **一处**，"开关碰撞层"与"占位美术的埋深"都从它派生 —— 分成两处写迟早会出现"看着在地上却打不到"。

### 1.3 触发与脱战判定

| 参数 | 建议意义 | 备注 |
|---|---|---|
| `trigger_radius` | 玩家进入多近算"靠近巢穴/巨树" | 用**平面**距离 |
| `trigger_dwell` | 要在圈内**停留**多久才登场 | 大纲原话是"靠近并停留一段时间"；离开圈内 → 计时清零 |
| `trigger_min_distance` | 离得太近不触发（可选） | 防止玩家贴着巢穴蹭触发 |
| `leash_radius` | 玩家跑出多远算脱战 | 应显著大于触发半径 |
| `leash_time` | 出圈持续多久才真脱战 | 防止玩家在边界反复横跳刷"回满血" |
| `return_speed_scale` | 回巢时的移速倍率 | 逃走过程也应可被看到 |

**判定取位置必须用玩家本体**：`player.get_node_or_null("Physics")`（或 `ViewFrustum.player_position()`）。**绝不读 `player` 根节点的 `global_position`** —— 根节点永不位移，读它得到的距离恒等于"出生点→Boss"，2026-09-22 已经在采集上炸过一次。这条要在 `BossSandwormBase` 里封成唯一入口 `_player_pos()`，谁都不许绕过。

**移速标尺（现役数值，实测自代码）**：玩家 `speed = 5.0` m/s；史莱姆 `move_speed = 1.5`。⇒ **Boss 移速建议落在 3.5 ~ 4.5**：跑得过玩家就没法"撤"，跑得和史莱姆一样慢则"撤"毫无压力、脱战机制形同虚设。

### 1.4 濒死（`FALLEN`）的精确规则

```
take_damage(d):
    if _untouchable: return                      # 第一行就拦
    if _state == GONE or _state == FALLEN: return
    _health -= d
    if _health <= 0:
        _health = 1                              # 保留最后 1 点
        _enter_fallen()                          # 置 _untouchable = true（永久，不是计时器）
    else:
        _on_hurt()
```

**必须处理的坑：一帧内多段伤害会越过"保留 1 点生命"。** 玩家一次挥砍用 `intersect_shape(..., 10)` 查询**最多 10 个碰撞体**，若 Boss 身上挂了多个碰撞形状、或同帧有第二个伤害源（弹幕 / 场地伤害），第二次 `take_damage` 就会把 1 点生命打光、直接走成 `dead` 逻辑。⇒ `_untouchable` 必须在**进入 `FALLEN` 的第一时间**置位，且是 `take_damage` 的首行检查。

### 1.5 受伤路径与体型约束

玩家攻击的实现（`script/player/physics.gd`）：

- `attack_range = 2.0`（半径 2 m 的**竖直圆柱**，高 2.6、中心 y = 脚下 + 1.0）
- `query.collision_mask = 0xFFFFFFFF`（**所有层**）
- `space_state.intersect_shape(query, 10)` —— **上限 10 个结果**
- 命中后 `_find_take_damage_node(collider)`：**沿父链向上找带 `take_damage` 的节点**

由此得到三条硬约束：

1. **Boss 只能有一个"承伤体"**：一个碰撞体 + 其祖先上有 `take_damage`。挂多个碰撞体会白占那 10 个名额，玩家站在怪堆里时可能查不到 Boss。
2. **判定体要贴在体表**：玩家的判定圆柱半径只有 2 m、中心高 1.0（玩家碰撞体只有 1.0 m 高）。Boss 体型巨大时，碰撞体必须覆盖体表，否则玩家站在它脚边也够不着任何 collider。
3. **`take_damage` 的签名保持 `func take_damage(damage: int) -> void`**，与 `Slime` / `Drone` / 玩家 `Physics` 一致 —— 沿父链查找是按方法名认的。

受击反馈的现成件：`FilterSystem.pulse()`（画面闪）+ `hurt` 动画。**不要**给 Boss 做 0.5 秒无敌帧（那是 mob 的做法），Boss 的受击节奏交给后摇和招式冷却控制。

### 1.6 身份与存档（**这一节是最关键的**）

#### 现状（读代码核实）

- 敌人由 `WorldStreamer` 统一管理：组名 `"enemy"`，记录在 `_enemy_records`。
- 存档条目：`{ "path": <相对当前场景的节点路径>, "position": {...}, "health": n }`，`path` 由 `current_scene.get_path_to(node)` 生成。
- `collect_enemies()`：**跳过 `_state == "dead"` 的个体**（"存了等于读档复活"）。
- `apply_enemies()`：**"存档里有的落位回血，存档里没有的（= 已被击杀）删掉"**；存档里给了但找不到记录的只打一行 warn 就跳过。
- 卸载/装配：按距离（`enemy` 半径 70 / 滞回 24），卸载＝`remove_child`（状态保留，**不 queue_free**）。

#### 为什么 Boss 不能直接套这套

| # | 冲突 | 后果 |
|---|---|---|
| 1 | "存档里没有 = 已击杀" | Boss 是"逃走但没死"，一旦某次存档没写进去，读档就把它当尸体抹掉 |
| 2 | `path` 是**节点路径** | Boss 是运行时生成/移除的，路径不稳定；它进不得 `map.tscn` 的固定节点树 |
| 3 | `collect_enemies` 跳过 `_state == "dead"` | 状态名不同步就会误判；Boss 根本没有 `dead` |
| 4 | **`map_generator_3d._place_enemies()` 会把组 `"enemy"` 的所有节点全部搬到丛林区**（沿 X 轴每 2 m 排开） | Boss 一出生就被传送到丛林区 |

#### 结论：Boss 另立门户

- **Boss 不进 `"enemy"` 组**，用新组 `"boss"`；`_place_enemies()` 一行都不用改（它只看 `"enemy"`）。
- **存档新开一段 `world.bosses`**：

```json
"bosses": [
  { "boss_id": "sandworm_surface", "state": "gone",    "health": 1,
    "position": {"x": 0, "y": 0, "z": 0}, "defeated": true },
  { "boss_id": "sandworm_mech",    "state": "dormant", "health": 900,
    "defeated": false }
]
```

- 读档规则（与 mob 相反，要写清楚）：
  - `boss_id` 在档里 **且** `defeated = false` → 落位 + 恢复 `state`/`health`；
  - `defeated = true` → **不生成实例**（它已经退场了，且场地已经变了）；
  - `boss_id` **不在档里** → 按"从没打过"生成（**不是**"已击杀"）。
- `boss_id` 取 `StringName` 常量，定义在各自的 Boss 脚本里（如 `Sandworm.BOSS_ID := &"sandworm_surface"`），**不要用节点路径当身份**。

#### 场地永久变化 → `WorldState`

巢穴坍塌、藤蔓长到第几天、浮空岛有没有坠落 —— 这些**不属于敌人存档，也不属于 v2 的地形快照**（地形快照只存 1600×1600 的瓦片）。

新增 `script/world/world_state.gd`：

```
class_name WorldState          # 纯静态，不用 autoload（项目约定：核心系统 = class_name + static）
static func set_flag(id: StringName, value: int) -> void
static func get_flag(id: StringName, default: int = 0) -> int
static func has_flag(id: StringName) -> bool
static func serialize() -> Dictionary
static func apply(data: Dictionary) -> void
static func reset() -> void      # 新开局必须清，否则上一局的旗标会漏进来
```

- 旗标命名：`&"sandworm_nest_state"`（0 完好 / 1 坍塌）、`&"vine_day"`、`&"skyisland_fallen"`。
- **枚举只能末尾追加**（`WorldState` 的值会进存档）；**对外集合必须 `.duplicate()`**。
- 新开档 / 回主菜单要 `reset()`。

### 1.7 招式数据化（`BossSandwormAttack`）

现有敌人的伤害是**动画回调 + 距离判断**：`slime.gd` 在 `_on_attack_animation_finished()` → `_apply_attack_damage()` 里判距离再扣血。这套做法**表达不了"前摇可躲"** —— 伤害时点绑死在美术动画长度上，改前摇就得改动画。

⇒ 新起 `script/ai/enemy/boss/sandworm/boss_sandworm_attack.gd`：

```
class_name BossSandwormAttack extends Resource
@export var attack_name: StringName
@export_enum("CYLINDER","SPHERE","RING","CONE") var shape: int
@export var radius: float
@export var height: float
@export var damage: int
@export var telegraph_time: float      # 前摇：给玩家跑的时间
@export var strike_time: float         # 判定的有效时长
@export var recover_time: float        # 后摇：玩家的输出窗口
@export var cooldown: float
@export var move_scale: float          # 前摇期间能否移动（0 = 定身）
@export var spawn_projectile: StringName   # 需要弹幕时用（复用 DroneProjectile）
```

- `BossSandwormBase` 只负责**按 `telegraph → strike → recover` 推进计时器**，具体判定形状由 `BossSandwormAttack` 描述。
- 一个 Boss 有 `Array[BossSandwormAttack]`，按距离/阶段挑一条（沙虫的地表阶段与机械阶段可以共用同一套招式表，只换数值）。
- 弹幕**复用 `DroneProjectile`**（`class_name` 已存在，`projectile.damage` 可外部设置）—— 注意它的演示弹道是"平行地面平射"，**必须飞 y ≤ 1.2**，否则打不到只有 1.0 m 高碰撞体的玩家。

### 1.8 玩家死亡时的处理【**已定：回 `DORMANT` + 回满血**】

> **2026-09-24 已拍板：采用下面的选项 ①**，并与"玩家拖太远"共用同一条离场路径，详见 2.5。

`RespawnSystem` 目前**完全不碰敌人**（只有 `register_spawn/set_respawn_point/on_died/tick/can_revive/clear_dead`）。所以玩家死在 Boss 战里、5 秒后原地复活，Boss 会继续按 `CHASE` 追过来。

三个选项：

| 选项 | 说明 | 代价 |
|---|---|---|
| **① Boss 回 `DORMANT` + 回满血**（**推荐**） | 与"脱战回满血"同一条规则，对玩家最宽容 | 需要玩家一死就通知 Boss（监听 `died` 信号，现有 `physics.died` / `RespawnSystem` 都可挂） |
| ② 保持现状 | 不改代码 | **会变成守尸**：复活点若在 Boss 仇恨圈内，玩家 5 秒后必然再死 |
| ③ 战斗作废但保留已扣血量 | — | 与大纲"必须一次打完"直接矛盾，不建议 |

## 2. 沙虫状态机（第一阶段：地表战）

> 本章把「1. 骨架」落到第一只具体 Boss 上。第二阶段的**机械沙虫是另一个实例**（另一个 `boss_id`），同构、只换数值与招式表，见 2.8。

### 2.1 玩家可见的行为（2026-09-24 与用户对齐）

1. 靠近巢穴并停留一段时间 → 沙虫钻出。
2. 沙虫**在一定距离内追击**玩家；进入攻击距离后出招。
3. 招式由两张表（血量高 / 血量低）决定，**从上往下取第一条不在冷却的**释放。
4. **玩家拖太远、或玩家死亡** → 沙虫回巢并**回满血**，回到待机（可重复发生，不推进世界）。
5. 血量被打到 1 → **保留最后 1 点生命 + 无敌**，逃回巢穴；**巢穴坍塌**，并打开"可进入"的锁。

### 2.2 状态图（规范化）

```
DORMANT --玩家进触发圈并停留--> EMERGING --动画播完--> CHASE
   ^                                                     |
   |                                        进攻击距离 --> 决策（按血量选表、选招）
   |                                                         |
   |                                            有可用招 --> 招式三段（前摇/判定/后摇）
   |                                                         |
   |                                            无可用招 <-- 结算完，回到决策
   |                                                         |
   +--- RETREAT <-- 拖太远 / 玩家死亡                          +--> 无可用招时回到 CHASE 继续追击

（任意招式命中，血量将被扣到 ≤ 0）--> FALLEN --逃走路径--> GONE --巢穴坍塌 + 开锁
```

**关键：这不是 `while` 循环，而是逐帧推进。**"回到检索技能列表"＝每次后摇结束时**重新决策**，不是跳回上一行代码。

### 2.3 与骨架（1.2）的差异

| 骨架态 | 沙虫的落地 | 差异 |
|---|---|---|
| `DORMANT` | 埋在巢穴（不可见 / 只留沙尘） | — |
| `EMERGING` | 钻出沙面动画（不可受伤） | — |
| `CHASE` | 按 `chase_speed` **追击**玩家 | **需要移速值**；本态内也判 `leash` |
| `TELEGRAPH`/`STRIKE`/`RECOVER` | 一次"招式三段" | 三段时长由 `BossSandwormAttack` 给（1.7） |
| `RETREAT` | 回巢 + **回满血** → `DORMANT` | **触发源从 1 个变 2 个**：拖太远 / 玩家死亡 |
| `FALLEN` | 1 血 + 永久无敌 + 逃离动画 | 由 `take_damage` **内部**触发，不由主循环触发 |
| `GONE` | 巢穴坍塌 + 开锁 | "开锁"本步只置旗标（见 2.6） |

### 2.4 决策点与招式表（原案"技能列表"的落地）

每只沙虫持两张招式表（都是 `Array[BossSandwormAttack]`）：`phase1_attacks`（HP > `phase_line`，默认 50%）、`phase2_attacks`（≤ `phase_line`）。
**数组的排列顺序就是出招顺序**：

| 表 | 顺序 | 内容 |
|---|---|---|
| 表 1（血 > 50%） | **①②③** | ①撕咬 → ②吐沙 → ③流沙陷落 |
| 表 2（血 ≤ 50%） | **④①②③** | ④潜行突袭 → ①撕咬 → ②吐沙 → ③流沙陷落 |

①②③ 在 `_build_attacks()` 里是**同一份 `shared` 声明**、两张表共用（不复制粘贴 ⇒ 杜绝"改了一张漏另一张、血量一破手感突变"）。

**决策点**（= 刚从 `CHASE` 进入攻击距离，或每次 `RECOVER` 结束）执行 `_pick_next_attack()`：

1. 按当前血量选表；表变了（跨过 `phase_line`）就先把轮转指针归零 —— 表 2 要**从 ④ 起手**才对得上"4123"；
2. 取**轮转指针指到的那一招**：
   - **够不着**（距离 > `max_range`）⇒ 返回"无招"，指针**不动**。调用方仍在 `CHASE` ⇒ 它会继续潜行逼近，**追进射程再放**（"潜近再放"）；
   - **在 CD** 或 **太近**（距离 < `min_range`）⇒ **顺延**到下一条；
3. **一圈都轮不到 → 不执行任何招，回 `CHASE` 继续贴身追。**

第 3 条是原案缺失的兜底，而且**对"会追击的 Boss"它是最自然的兜底**：没招可放就继续贴身追，而不是原地发呆。

- ⚠ **`min_range` 陷阱**：严格顺序 + "够不着就等" ⇒ 一旦给某招设了 `min_range > 0`，玩家贴脸时它会"永远够不着"、站着不动。目前所有招 `min_range` 都是 0，就是靠这条规避的；真要加，得同时补一条"太近就顺延"的分支。
- CD 是**每招一个 `float` 计时器**（不是全局一个），`delta` 递减；伤害判定发生在 `STRIKE`。固定轮转下轮到自己要隔一整轮（约 8 s+），所以 CD 基本拦不到 —— 保留它是防"改表改坏"。
- **相位切换只发生在决策点**：血量跨过 `phase_line` 后，下一次决策才换表，招式播到一半不切。
- 三段语义：`telegraph`（**露头才可被打**；`move_scale = 0` 则定身）/ `strike`（判定生效）/ `recover`（玩家的输出窗口）。每招"何时露头"由 `surfaces_in_telegraph` 定，见 2.4.1。
- **顺序轮转**（2026-09-26 从"从上往下取首条"改过来）：老版技能 1 永远优先，玩家一拉开距离就只可能见到远程招；新版①一定最先出、②紧跟其后 —— 顺序本身是留给玩家**背板**的。
- **判定形状有三种**（字段都在 `BossSandwormAttack`）：就地圆形 / **面前扇形**（`arc_degrees`，基准是**逻辑朝向 `_facing`**）/ **弹道**（`projectile_speed`，射出去之后命中与扣血归 `boss_sandworm_spit.gd`；配 `projectile_count > 1` 就是**连吐**）。
  - ⚠ 扇形与弹道的朝向/命中**一律不许读 `Visual`** —— 那是表现层，接正式美术时会换成 `SpriteFacing`；判定不能跟着表现层一起改。
  - ⚠ 弹道的伤害**落在三段之外**（见 2.4.1 ②），"前摇不扣血"这条不变式对它仍然成立，但"后摇不扣血"**不成立**；连吐之后"每个 `attack_id` 只扣一次"也**不成立**（§2.9 用例 12 已按这两条改）。
- **前摇必须有看得见的信号**：地面预警片（形状与朝向都从判定字段派生）+ 体色脉动，见 2.4.2。

#### 2.4.1 沙虫的四招（2026-09-26 定稿）

| # | 招式 | id | 伤害 | 判定形状 | 射程 | 前摇 | 判定 | 后摇 | CD | 何时露头 |
|---|---|---|---|---|---|---|---|---|---|---|
| ① | 撕咬 | `bite` | 18 | **面前扇形** 120°（半径 4.5） | 0–4.5 | 0.9 | 0.2 | 1.0 | 4.0 | 前摇就冒头 |
| ② | 吐沙 | `sand_spit` | 6 ×4 | **弹道 · 连吐 4 发**（18 m/s，命中半径 0.9，间隔 0.16 s） | 0–16 | 0.75 | 0.6 | 1.2 | 5.0 | 前摇就冒头 |
| ③ | 流沙陷落 | `quicksand` | 30 | 圆形区域（半径 7.0） | 0–20 | 2.8 | 0.3 | 1.8 | 6.0 | 判定段才破土 |
| ④ | 潜行突袭 | `dash_bite` | 12 | 圆形（半径 4.0） | 0–6 | 0.35 | 0.2 | 1.2 | 6.0 | 判定段才破土 |

- **① 撕咬**：从地下探出头咬一口 → 后摇。只在贴近时被选中（`max_range` = 半径 4.5）；前摇 0.9 s × 满速 5.0 ≈ 4.5 m，正好够"从嘴边跑到判定圈外"。
  - **判定是"面前扇形"，不是脚下一个圆**：够得着还不够，还得在**嘴前面**（左右各 60°）。
  - ⚠ 朝向在**开始前摇那一刻就锁定**（定身招不前摇转向）⇒ 贴脸时"**绕着它转**"也能躲开这一口（2 m 处横移 ≈3.5 m 就出扇形）。**这是"扇形"相对"圆圈"多出来的那条活路**，也是 §2.9 用例 16 钉死的东西。
  - **前摇有可见信号**（2026-09-26 用户反馈"不够明显"补的）：地面上画出**同一块扇形**，形状与朝向都和判定同源 ⇒ 玩家一眼看懂"往侧面跑"。见 2.4.2。
- **② 吐沙**：从地下探出头朝玩家**连吐 4 发沙弹** → 后摇。判定段只负责"射出去"，命中与扣血都归沙弹（`boss_sandworm_spit.gd`）。
  - 判定段按 **0.16 s 的节拍**吐满 4 发（0 / 0.16 / 0.32 / 0.48 s），**每一发都瞄"那一发出膛的瞬间"玩家在哪**。
  - **「躲的是飞行段，不是前摇段」**：所以前摇里站哪都没用 —— 必须在沙弹飞到之前横移出命中半径（0.9 m）。
  - **站定不动 = 4 发全吃（24 点）**；**持续换位 = 能甩掉后面几发**。距离决定难度：3 m 处飞行只要 0.17 s ⇒ 满速也只挪 0.85 m（< 0.9）⇒ 必吃满；10 m 处飞行 0.56 s ⇒ 能挪 2.8 m ⇒ 从容躲掉。**越近越该跑，别贴着它站桩**。
  - ⚠ 判定段的真实长度走 `strike_window()` = `max(strike_time, 末发时刻 + 0.05)` —— 表里的"判定 0.6"对连发招只是**下限**，配小了也不会"只吐 2 发就进后摇"。
  - ⚠ 沙弹的伤害**落在招式三段之外**（可能在它的后摇、甚至 Boss 已经回 `CHASE` 之后才落地），所以它靠 `struck` 信号回传、由 Boss 转报 `attack_landed`，**不许从当前招式反查**。
  - 不再画地面圈（`aims_at_player` 已去掉）：地面圈是给"落点钉在地面"的招用的。
- **③ 流沙陷落**：以玩家为圆心圈一块流沙地，圈内**所有单位**（玩家 + 其他生物）被**持续拖向圆心**；2.8 s 后沙虫从**圆心破土**，把还留在圈里的单位一口吞掉 → 后摇。应对方式是**走位**（逆着拉力走出去）而不是输出 —— 它的前摇在地底，打不到它。
- **④ 潜行突袭**：在地下高速逼近（`move_scale = 2.5` ≈ 8.5 m/s），0.35 s 后破土咬一口 → 后摇。判定圆心取**咬下去那一刻它自己所在的位置**，所以本质是一记短扑；站桩必中、边退边打能躲。

数值全部是 `@export` 建议值，写在 `sandworm.gd` 的 `_build_attacks()` 里（改数值状态机一行都不用动）。

#### 2.4.2 前摇的可见信号（2026-09-26 用户反馈"不够明显"）

用户反馈「撕咬释放时不够明显，玩家难以察觉」。光让**体色变红**只能传达"它要出手了"，
传达不了"**该往哪躲**"。所以前摇固定给两路信号：

| 信号 | 实现 | 覆盖的招 |
|---|---|---|
| **地面预警片** `ZoneFx`（`top_level`，钉在世界坐标上） | 区域招画**圆**（流沙的圈）、扇形招画**同形状的扇形**（撕咬的"嘴前面那块地"） | ①②③ |
| **体色脉动**（`_refresh_body_color()` 逐帧刷） | 在 `telegraph_color` 与其压暗版之间按 `telegraph_pulse_hz`（默认 3.2 Hz）跳动 | 全部 |

- **预警片的形状与朝向都和判定同源**：`_apply_marker_shape()` 读 `is_sector()` / `arc_degrees`，
  `_marker_yaw()` 读 `_facing` ⇒ 不会出现"预警片朝东、判定朝西"（与 1.2 规则 6 同一个口径）。
- 扇形是**手工拼的平面三角扇**（`_build_arc_mesh()`，按 (半径, 张角) 缓存），材质关掉背面剔除。
- 越接近爆发越暗、alpha 越高（`_update_zone_fx()`）—— 顺带给玩家一个"还剩多久"的读数。
- **判定段一开始就收起来**（`_enter_strike()` → `_hide_zone()`），不会残留到出完招。
- 对撕咬来说，预警片正是一张"**这块地危险**"的图：贴着地面的扇形，往侧面走两步就出范围。


### 2.5 离场：拖太远 / 玩家死亡（本次新增）

| 触发 | 条件 | 结果 |
|---|---|---|
| 拖太远 | 玩家平面距离 > `leash_radius` 且持续 `leash_time` | `RETREAT` → 回巢 → **回满血** → `DORMANT` |
| 玩家死亡 | 玩家 `died` 信号（挂 `Physics.died`） | 同上 |

- **两者共用同一条 `RETREAT` 路径、同一结果**，只区分触发源（写日志用）。
- `RETREAT` **不写任何世界状态**、可无限重复 ⇒ 反复消耗磨不死它（对应大纲 5.1.2）。
- 回血是 **回满**，不是回一部分。
- **必须接"玩家死亡"这一条**：`RespawnSystem` 现在完全不碰敌人，不接就会出现"守尸"（复活点若在仇恨圈内，5 秒后必再死）。
- 判距离一律走 `_player_pos()`（读 `player/Physics`），**绝不读 player 根节点**（见 1.3）。

### 2.6 濒死与终局

- 1 血的夹取发生在 `take_damage()` **内部**（见 1.4）：`_health = maxi(_health, 1)` 并**立刻**置**永久** `_untouchable`。
  **不是**等主循环"查到血量等于 1" —— 一次扣 10、血量剩 5 → −5，此时 `>50%` / `1<x<50%` / `==1` 三个分支**一个都不命中**，状态机会卡死。
- `FALLEN`：`_untouchable = true`（永久，不是 0.5 秒计时器）→ 播逃离动画 → 走完路径进 `GONE`。
- `GONE`：播巢穴坍塌动画，并置 `WorldState` 旗标 `&"sandworm_nest_state" = 1`。
- **"打开巢穴可进入的锁"本步只做"置旗标 + 巢穴碰撞/外观切换"**：跨场景能力不存在（`change_scene` 在 `script/` 里全文零命中，只有同场景内 `teleport_player_to_start`），真正的"走进实验室"归第 3 章。

### 2.7 存档（复用 1.6 的 `world.bosses`）

```json
{ "boss_id": "sandworm_surface", "state": "dormant", "health": 900, "defeated": false }
```

- 战斗中存档（`CHASE`/`TELEGRAPH`/…）：落位 + 恢复 `health`，但 `state` **一律回落到 `DORMANT`**（避免读档瞬间从半张地图外冲过来）；**CD 不存**，读档重置为 0。
- `FALLEN` 尚未走完就存档 → **直接按 `GONE` 落**（避免读档后重播逃离/塌陷）。
- `defeated = true` → **不生成实例**（场地已经变了）。
- `boss_id` **不在档里** → 按"从没打过"生成（**不是**"已击杀"，与 mob 的语义相反）。

### 2.8 与机械沙虫（第二阶段）的关系

同一套骨架 + 招式表结构，换 `boss_id = &"sandworm_mech"`、换数值与招式表。`RETREAT` 的触发在实验室里退化成"玩家逃出房间"——**复用同一个 `leash` 机制**，只是半径按房间尺寸给。

### 2.9 测试用例（在 1.10 的七条之上追加）

| # | 用例 | 断言 |
|---|---|---|
| 8 | 追击与脱战 | 玩家在 `leash_radius` 内移动 → 沙虫朝玩家位移；移出且持续 `leash_time` → `RETREAT` |
| 9 | 玩家死亡离场 | 触发 `died` → `RETREAT` → 回巢后 `health == max_health` 且 `state == DORMANT` |
| 10 | **招式表兜底** | 全表 CD 拉满 / 玩家在全部 `max_range` 外 → 决策返回"无招"，状态回 `CHASE`，**不卡死、不空放** |
| 11 | 相位切换时机 | 血量 60% → 40% → **下一次决策点**才换 phase2 表（招式中间不换） |

| 13 | **同步重入** | 招式判定把玩家打死 → 玩家同步发 `died` → 状态机在 `_process_attack` 中途被重入进 `RETREAT`、`_attack` 被置 `null` → **不报错、不空引用**（见 1.4 的坑） |
| 14 | **受击窗口** | 等 ① 撕咬前摇（`collision_layer != 0` 且 `take_damage` 生效）；等 ③ 流沙前摇 ⇒ 仍在地底（`collision_layer == 0`、`take_damage` 无效、`current_attack_id()` 仍是 `&"quicksand"`） |

### 3.3 实装时与规格的差异（改这里要同步回来）

1. **`RETREAT` 与 `FALLEN` 共用 `_process_going_home()`**，走到巢穴才分道扬镳：一个"回满血 → DORMANT"，一个"→ GONE"。
2. **同帧多段伤害的防线就是 `take_damage` 的第一行 `_untouchable`**，不靠主循环回头查血量。
3. **相位切换是"隐式锁存"**：没有额外的 `_phase` 字段，`_current_table()` 只在决策点被调用，所以"招式播到一半不换表"是自然结果（有断言守着）。门槛真值在 `@export phase_line`（默认 0.5），`current_phase()` 与 `_current_table()` 共用它。
4. **`_face()` 只转占位 `Visual` 的 yaw**。接正式美术（`SpriteFacing`）时**必须删掉它**，否则会与 SpriteFacing 抢 `Visual` 的 basis。
5. 占位表现：待机埋在 `-buried_depth`、**潜地追击埋在 `-travel_depth`（默认 1.9 m，只露一截背脊）**、登场/露头抬到 0、前摇体色**脉动**（在 `BossSandwormAttack.telegraph_color` 与其压暗版之间跳，见下面第 14 条）—— 正式美术接入后全部由动画取代。埋深由 `_visual_target_depth()` 统一算，与受击窗口同源。
6. `BossSandwormBase` 里多了三个**只给测试场地用**的方法：`debug_wake()` / `debug_damage_to()` / `debug_set_all_cooldowns()`。正式逻辑不要依赖它们。
7. **受击窗口 = 切 `collision_layer`（`8` ↔ `0`），不切 `collision_mask`**。玩家挥砍走 `physics.gd` 的 `intersect_shape`（`collision_mask = 0xFFFFFFFF` 扫全部层），所以 layer 置 0 就字面意义"打不到"；mask 保持 `2`（地面）⇒ 潜地时依旧站立、不坠落，也不会变成"看不见的墙"。同款先例见 `resource_manager.gd` 隐藏建筑。
   - 判据**只有一处**：`_is_surfaced()`（TELEGRAPH 看 `attack.surfaces_in_telegraph`、STRIKE/RECOVER 恒真、其余恒假）。`_set_state()` 每次切状态都调 `_refresh_hitbox()`，所以"看着在地上却打不到"不可能出现。
   - `BossSandwormState.can_be_hurt()` 也去掉了 `CHASE`，它只是**静态规则**；运行时真判据是 `_is_surfaced()`。
8. **顺序轮转**：`_rotation_index` 指针 + `_pick_next_attack()`。够不着 ⇒ 返回"无招"且**不推指针**（这就是"潜近再放"）；CD / 太近 ⇒ 顺延；一圈没有 ⇒ 回 `CHASE`。`_sync_rotation_with_phase()` 在换表时把指针归零 —— 表 2 才读得出 4123。`_reset_cooldowns()` 也一并归零。
9. **`take_damage` 与 `debug_damage_to` 分层**：共用核心 `_apply_damage()`；`take_damage` 三道门（`_untouchable` → `can_be_hurt` → `_is_surfaced`）之后调它，`debug_damage_to` **绕过受击窗口**（否则摆血量变成看沙虫脸色的运气活），只保留 `_untouchable` 拦。
10. **流沙吸引改 `global_position`，不塞 `velocity`**：玩家控制器每帧自己重算 velocity，塞初速会被覆盖。被拉的对象走**组名遍历**（`player` 组解引用到 `Physics` 子节点 + `enemy` 组），不用物理查询 —— 测试假玩家没有 `CollisionShape`。
11. **扇形判定的基准是 `_facing`（逻辑朝向），不是 `Visual` 的 yaw**：`_face()` 现在同时更新两者，但只有 `_facing` 参与判定。定身招（`move_scale = 0`）在前摇里**不调 `_face()`** ⇒ 朝向自然锁住，"绕背咬空"就是这么来的。
12. **弹道（沙弹）自己带 `attack_id`，`connect` 时不用 `bind()`**：`.bind()` 的参数是**接在信号参数后面**传给回调的，顺序极易写反 —— 2026-09-26 就炸成 `Method expected 2 argument(s), but called with 3`。同一轮把 `test/signal_arity_check.py` 补上了"带 bind 的 connect"这一项（它原先直接 `continue` 跳过）。
13. **沙弹的命中判定 = "本帧扫过的线段 ↔ 目标的**平面**距离"**，不碰物理：① 用线段而不是当前点 ⇒ 换帧率/加速度都不会隧穿；② 只看平面距离 ⇒ 平射弹道不会"从玩家头顶飞过"（无人机弹幕踩过的坑）。
14. **前摇的可见信号走两个通道**（2026-09-26 用户反馈"撕咬不够明显"）：
    - **地面预警片** `ZoneFx`（**`top_level`**，钉在世界坐标上 —— 不跟着沙虫走，否则圈会追着玩家跑，等于取消"跑出去就能躲"）：区域招画圆、**扇形招画同形状的扇形**。形状读 `is_sector()` / `arc_degrees`（`_apply_marker_shape()`），朝向读 `_facing`（`_marker_yaw()`）⇒ **形状与朝向都和判定同源**，不会出现"预警片朝东、判定朝西"。扇形是手工拼的平面三角扇（`_build_arc_mesh()`，按 (半径, 张角) 缓存），材质关背面剔除。
    - **体色脉动**：不再是静态变红，而是在 `telegraph_color` 与其压暗版之间按 `telegraph_pulse_hz`（默认 3.2 Hz）跳动 —— 静态变色在余光里抓不住注意力。
    - 判定段一开始（`_enter_strike()`）就 `_hide_zone()`，不会残留到出完招。
15. **连发 = "判定段按节拍多结算几次"**，不是"一次结算、多发共用一个时点"：`_shots_fired` / `_shot_total` 取代了老版的 `_strike_done`（非弹道招 `shot_count()` 恒为 1，语义与老版等价）。**离开判定段的条件改走 `strike_window()`**，`strike_time` 对连发招降级为**下限** ⇒ 即使 `strike_time` 配小了也不会"只吐 2 发就进后摇"。
    - 所以 §2.9 用例 12 的两条不变式都随之收窄：`后摇不重复扣血` 只对**非弹道招**成立，`每招只扣一次` 只对**就地判定**的招成立。
