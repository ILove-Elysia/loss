本文规定 `loss-land/art/` 的目录结构、命名规则和迁移操作。目标是让"给引擎用的资产"和"下载来的原始素材包"彻底分开，并且再也不要因为挪文件而弄坏游戏里的图。

## 二、两条底线原则

### 1. 被引用的文件不许动

Godot 的资源引用是写在 `.tres` / `.tscn` 文件里的路径字符串，形如：

```
res://art/icons/log.png
```

文件一挪，这个路径就失效。**失效是静默的**——不报错、不弹警告，只是图标变成空白。等你在游戏里发现物品图标全没了，已经很难定位到是哪次移动造成的。

`art/icons/`、`art/player/`、`art/enemies/` 属于这一类。想把它们整理得更"整齐"，收益远小于风险。要改必须走第五节的迁移流程。

> `player/` 已按**角色维度**拆分完毕（原先平铺的 `char_blue/green/red.png` 移入各自的角色目录）。
> 之后新增角色直接在 `player/` 下建目录，不要往根下平铺。

### 2. 原始素材包必须整体保留

第三方包的价值不只在图片。每个包里通常还有：

- `readme.txt` / `LICENSE` / `Terms.txt` —— 授权凭证，将来被质疑素材来源时这是唯一证据
- 精灵表说明 —— 每张图多少列多少行、单帧多大、动画顺序
- 原始工程文件 —— 如 Pixel Crawler 包里的 `.aseprite`，可以继续编辑

所以第三方包**整包搬、不许改内部文件名**，统一放进 `art/_source/`。这个目录引擎不引用，可以随便整理，不影响游戏。

`art/_source/` 里 12 个包中有 8 个带 readme 或授权文件，别丢。

## 三、踩过的坑：两处真实的引用断裂

第一次按"零引用"的判断搬完目录后，有两处引用断了。记在这里，因为它们暴露的是方法问题，不是运气问题。

### 坑 1：只 grep 了 `script/` 和 `scene/`，漏了 `tscn/`

预制体都在 `tscn/prefab/` 下，不在 `scene/` 下：

- `tscn/prefab/grass_entity.tscn` → 引用 `art/oak_woods_v1.0/decorations/grass_1/2/3.png`
- `tscn/prefab/slime.tscn` → 引用 `art/art/Forest_Monsters_FREE/Mushroom/...` 6 张

这两个包因此**当时**没能进 `_source/`：`oak_woods_v1.0` 留在原地，`Forest_Monsters_FREE` 归到 `art/enemies/`。

> **后续（2026-09-18 复查）**：两者的真实处境并不相同。
> `Forest_Monsters_FREE` 是**真在用**——`slime.tscn` 挂了它的 6 帧动画，永久归 `enemies/`。
> 而 `oak_woods_v1.0` 的引用者 `grass_entity.tscn` **自己就是废弃孤岛**（全工程无人加载），
> 所以它最终仍被移进了 `_source/`（连同那个废场景一起）。**这一步的结论需要引用者还活着才成立。**

**教训 1：查引用要查全工程，不是查几个目录。**

**教训 2（更隐蔽）：光看"有人引用"不够，还要看引用者自己是否活着。** 引用链的末端如果是个废弃文件，那这条链是死的——只做一层引用检查会把它误判成"在用"。

### 坑 2：二进制 `.res` 内部的引用 grep 不到

`art/tiles/tileset_test.res` 是二进制资源（文件头 `RSRC`），它内部存着：

```
res://art/oak_woods_v1.0/oak_woods_tileset.png
```

普通 `grep` 对这种混合二进制文件要么跳过、要么因为行太长而看不出上下文。而且**二进制资源里的字符串带长度前缀，改路径长度会直接损坏文件**——所以这类文件的引用只能通过在编辑器里拖拽来更新，不能手工改字符串。

> **现状**：`tileset_test.res` 本身零引用者，已于 2026-09-18 移出工程（`trash_2026-09-18/`），这条约束随之消失。
> 但只要将来还有二进制 `.res` 留在工程里，这个坑就依然成立。

### 坑 3：`.tscn` / `.tres` 的"自引用"会让孤岛扫描整类失效

`.tscn` 和 `.tres` 会在**文件头声明自己的 uid**：

```
[gd_scene format=3 uid="uid://bdral3goqm52c"]
```

`test/find_orphans.py` 初版把这条也当成"一次引用"，于是**每个场景/资源都在引用自己**——`.tscn`/`.tres` **永远不可能被判为孤岛**，整类漏报。

排除自引用后立刻暴露两个藏了很久的废弃文件：`tscn/prefab/grass_entity.tscn`、`tscn/test.tscn`。

**教训：任何"引用关系"工具，第一步都要把自引用排除掉。**

### 配套工具（已加入 `test/`）

这三个坑之后，校验工具补上了：

| 脚本 | 作用 |
|---|---|
| `test/check_data_refs.py` | 已扩展：扫描全工程的 `.tres` / `.tscn` / `.res` / `.gd`，校验每一条 `res://` 引用是否存在；并检查 `art/` 下每个图片是否缺 `.import` 伴随文件 |
| `test/fix_import_paths.py` | 批量移动文件后，同步 `.import` 内 `source_file` 字段与实际位置 |
| `test/find_orphans.py` | 按引用图反推**未被引用**的文件（已排除自引用）。注意**孤岛 ≠ 可删** |

**改完资产目录，这两个脚本必须跑，最后再实机确认。**

## 四、命名规范

### 通用规则

- 全小写 + 下划线分隔
- 禁止空格、中文、大写字母、连字符
- 序号统一两位补零：`_01`、`_02`，不要 `_1`

> 注：`art/enemies/Forest_Monsters_FREE/` 是第三方包名，保留原状不改。`art/_source/` 内的所有包同样保持原状（`_source/README.md` 列了全部包名）。
> 第三方包名含空格/大写/点号（如 `Pixel Crawler - Free Pack`）不受本规范约束，这是刻意的——改名会让将来核对授权文件时对不上。

### 分类规则

| 类型 | 格式 | 示例 |
|---|---|---|
| 物品图标 | `<物品id>.png`，与 `script/items/data/<id>_item.tres` 的 id 完全一致 | `iron_axe.png` |
| 角色精灵表 | `player/<角色id>/char_<配色>.png`（**一角色一目录**） | `player/adventurer/char_blue.png` |
| 序列帧 | `<对象>_<动作>_<序号>.png` | `slime_idle_01.png` |
| 头像 | 角色专属头像放该角色目录：`player/<角色id>/portrait.png`；其余 `<对象>_portrait.png` | `player/adventurer/portrait.png` |
| 瓦片集 | `tileset_<地形名>.png` / `.res` | `tileset_beach.res` |
| 界面元件 | `ui_<用途>_<变体>.png` | `ui_panel_dark.png` |
| 特效 | `fx_<用途>_<序号>.png` | `fx_hit_01.png` |

**物品图标的命名规则是硬性的。** 图标文件名必须和被引用的 `item.tres` 的 id 一模一样。这条规则存在的意义是：看到一个文件名就知道去哪里找对应的数据文件。

## 五、迁移操作手册

### 第一步：备份

```bash
cd "E:/GameMake/loss"
cp -r loss-land/art art_backup_$(date +%Y%m%d)
find loss-land/art -type f | wc -l    # 和备份目录的文件数对一下
```

### 第二步：查清引用（最关键的一步）

```bash
cd "E:/GameMake/loss/loss-land"
python test/check_data_refs.py    # 会列出所有断链
python test/find_orphans.py       # 反查：哪些文件没有任何引用（含"引用者是死的"这条链）
```

对照结果确认：哪些目录被引用、**被谁引用**。**不要凭"我以为没人用"下判断。**

更关键的是**追问一层：引用者自己还活着吗？** 看到"有人引用"就放过，会把挂在废弃文件上的资产误判成在用（`oak_woods_v1.0` 就是这么被判过一次）。判断依据是 `find_orphans.py` 的孤岛清单——**引用者出现在孤岛清单里，这条引用链就是死的。**

### 第三步：搬零引用的部分

`art/_source/` 里的东西关不关编辑器都无所谓，直接在文件管理器里拖。注意：

- `.png` 和它的 `.png.import` 必须一起移动，不能分开

### 第四步：搬被引用文件（走完整流程）

编辑器拖拽**只对 `.tres` / `.tscn` 里的引用有效** —— 脚本里手写的路径字符串它改不了。
所以被 `.gd` 引用的文件必须在编辑器外移动 + 手工改脚本：

1. `cp -r` 备份该目录
2. 移动 `.png` 与 `.png.import`（必须成对）
3. 手工改**所有**引用点 —— 至少查 `script/`、`scene/`、`tscn/` 三处；
   二进制 `.res` 内部引用 grep 不到，只能靠 `check_data_refs.py` 兜底
4. `python test/fix_import_paths.py` 同步 `.import` 的 `source_file`
5. `python test/check_data_refs.py` + `python test/gd_static_lint.py` 校验
6. 重启 Godot，实机确认

若引用**全在** `.tres` / `.tscn` 里（没有 `.gd` 字面量路径），用编辑器拖更省事：

1. 打开项目，等文件系统面板扫描完成
2. 在 FileSystem 面板里拖拽到目标位置
3. 编辑器自动重写所有引用

**绝对不要在编辑器关闭时用文件管理器移动被引用的文件、又不改引用。**

### 第五步：校验

```bash
cd "E:/GameMake/loss/loss-land"
python test/fix_import_paths.py   # 同步 .import 内的 source_file
python test/check_data_refs.py    # 校验所有 res:// 引用存在
python test/gd_static_lint.py     # GDScript 静态检查
```

最后**实机确认**，重点看：物品图标显示完整、角色外观正确、地形贴图正常、史莱姆动画正常。

## 八、禁止事项

- 禁止改名或移动 `art/icons/`、`art/player/` 里的文件，除非走第五节的完整流程
- 禁止把角色贴图平铺在 `art/player/` 根目录 —— 必须放 `art/player/<角色id>/`，角色一多就分不清哪张是谁的
- 禁止改名或移动 `art/enemies/` 里**被引擎引用**的文件（`Forest_Monsters_FREE/Mushroom/Mushroom with VFX/` 那 6 张）。
  同包内**未被引用**的帧可以归入 `_source/`——2026-09-22 就把 `Mushroom without VFX/`（7 张）与 `Mushroom-AttackWithStun.png` 一并归入 `_source/_loose/Forest_Monsters_Mushroom_unused/`。
  > 原禁令写的是「内部任何文件都不许动」，那是在包整体在用、怕误伤 `slime.tscn` 的 6 条引用时立的；后来实测这 8 张零引用、`check_data_refs.py` 全过，遂把规则收窄为「按是否被引用区分」。**动 `enemies/` 里任何文件后，必须跑一次 `check_data_refs.py` 并确认 `slime.tscn` 的 6 条路径仍在。**
- 禁止把 `.blend` / `.psd` 等源工程文件放进 `art/`（`_source/` 内的第三方 `.aseprite` 例外，那是包自带内容）
- 禁止丢弃第三方包的 `readme` / `LICENSE` / `Terms.txt`
- 禁止在 `_source/` 里重命名文件，保留原始名字才能对照作者的说明文档
- 禁止把试验性、临时的图直接丢进 `art/`，放 `_wip/` 或者工程外面
- 禁止在没跑 `check_data_refs.py` 的情况下提交资产目录变动
