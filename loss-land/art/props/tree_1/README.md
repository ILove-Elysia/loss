# art/props/tree_1 — 树（世界资源物外观）

**一棵树一个目录。** 树的原始帧序列、帧动画定义都放这里，别平铺到 `art/props/` 本层。

```
art/props/tree_1/
├── tree_1/                      25 张帧序列（styled_final2.png0000.png … 0024.png，1000×1200）
└── tree_frames.tres             SpriteFrames：把 25 帧组织成 3 个动画
```

---

## 这 25 帧到底是什么

**是「风吹摆动」循环，不是砍伐形变。** 实测帧间差异：

- 帧 0 = 帧 12 = 帧 24（逐像素完全相同）
- 差异从帧 0 递增，帧 17~18 达到最大（约 7.9% 的像素有变化），然后回落
- 也就是说：一个「静止 → 摆到最开 → 摆回静止」的完整往返

所以它天然适合做**待机摆动**。目前 `growing` 只取帧 0（静止的树），摆动的 24 帧用在砍伐反馈和备用待机上。

---

## tree_frames.tres 里的三个动画

| 动画名 | 帧 | 速度 | 循环 | 用途 |
|---|---|---|---|---|
| `growing` | 帧 0（单帧） | — | 是 | **默认外观**：立在那里不动的树 |
| `chop` | 全部 25 帧 | 30 fps（≈0.83 s） | **否** | **被砍时播放**，播完停在最后一帧 |
| `sway` | 全部 25 帧 | 7 fps | 是 | **备用**：待机时树叶随风轻摆 |

**启用待机摆动**：把 `script/resources/data/tree_data.tres` 的 `growing_animation` 从 `"growing"` 改成 `"sway"` 即可，无需改任何代码。

**`chop` 的速度是有意对齐的**：树的 `harvest_time` 是 0.8 秒，25 帧 @30fps ≈ 0.83 秒 —— 玩家站在原地砍树的这段时间里，动画正好播完。

## 世界尺寸与落地锚点

贴图 1000×1200、内容并集 bbox = x 119~969 / y 164~1039（树干底部中心在 x≈497，基本居中，无需水平偏移）。

`tscn/prefab/tree.tscn` 里的取值：

| 项 | 值 | 说明 |
|---|---|---|
| `pixel_size` | 0.004 | 贴图矩形 = 4.0 × 4.8 米 |
| 树的内容高度 | **3.5 米** | 约玩家（1.48 米）的 2.4 倍 |
| 树冠宽度 | ≈ 3.4 米 | 与 `min_distance` 5 米配合，成林时长不重叠 |
| Sprite 节点 `position.y` | **1.756** | 把贴图矩形上抬，使树干底部**正好落在 y = 0** |
| 树干碰撞体 | 半径 0.45 / 高 2.0，中心 y = 1.0 | 只挡树干，树冠不挡路 |

> `1.756` 怎么来的：贴图矩形高 4.8 米，`centered` 后以节点为心，所以矩形顶在节点上方 2.4 米处；树干底在图内第 1039 行，换算成世界坐标比矩形顶低 1039×0.004 = 4.156 米；要让它在世界 y = 0，节点就得抬到 4.156 − 2.4 = 1.756 米。
> **改 `pixel_size` 就必须同步重算这个值**，否则树会悬空或陷进地里。

## 使用者

`tscn/prefab/tree.tscn` 是唯一使用者：`Sprite(AnimatedSprite3D)` 挂 `tree_frames.tres`，`billboard = 2`（Y 轴广告牌，永远面向摄像机、但不随俯角倾倒），`Visual` 节点挂 `ResourceVisual` 把精灵接进资源的采集/再生状态机。
